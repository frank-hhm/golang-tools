# 文件查看器工具页（/tools/viewer）

## 目标与形态
新增一个独立工具页 `文件查看器`：左栏本机文件浏览（复用磁盘管理能力），右栏按扩展名/内容判定类型分别 **看图 / 预览 / 编辑**。核心边界（已与用户确认）：
- 编辑：纯文本/代码（CodeMirror6，含语法高亮 + 行号 + 可保存写回）。
- 查看：图片、mp3/mp4（原生播放器组件）、pdf、excel（表格化），以及 json/xml/log/ini/yaml 等文本。
- 传输：文本/图片/PDF/Excel 走 base64（带上限，超限回退）；音视频走 Range 流式端点。
- 无法预览的二进制：给信息卡 + 「系统程序打开」/「下载」/HEX 前若干字节。

## 一、Go 后端：新增 tools/fileview 包 + services/app 绑定
新建 `tools/fileview/fileview.go`（纯文件系统逻辑，跨平台、零 cgo），对外提供：

- `type FileText struct { Content string; Size int64; Truncated bool; Binary bool }`
- `ReadText(path string) (FileText, error)`：`filepath.Abs`+`os.Stat`（目录报错），读上限 `maxTextInline = 2<<20`；用 `bytes.IndexByte(buf,0)` 与 `utf8.Valid` 判二进制（沿用 [client_sftp.go](file:///e:/test/golang-tools/tools/ftp/client_sftp.go) 的 `previewTextMax` 判定写法），二进制时只回小段并置 `Binary=true`。
- `WriteText(path, content string) error`：仅覆盖已存在文件，临时文件 + `os.Rename` 原子写回；写前 `maxTextInline` 上限校验。
- `type FileBinary struct { Kind string; DataURL string; Size int64 }`（Kind: `inline` | `tooLarge`）
- `ReadBinaryDataURL(path, mime string) (FileBinary, error)`：`os.ReadFile`+base64 拼 `data:<mime>;base64,...`；`size > maxBinInline = 25<<20` 时返回 `tooLarge`（前端改用流式端点或下载）。
- `OpenSystem(path string) error`：`sysx.Open().File(path)`（headless Linux 无 xdg-open 时自然返回 `sysx.ErrUnsupported`）。

在 [services/app](file:///e:/test/golang-tools/services/app) 新建 `fileview.go`，加薄绑定（**均跨平台、无 build tag**，符合 AGENTS「绑定方法不能藏在 build tag 后面」）：
`FileReadText`、`FileWriteText`、`FileReadBinary`、`FileOpenSystem`。这些方法在 server 构建里同样存在（Linux 面板浏览的是服务器本机文件）。

### 类型判定
`kind` 由「扩展名 → MIME → 内容嗅探」三级决定，放 `tools/fileview` 内 `Classify(path) (kind, mime)`，kind ∈ `image|pdf|sheet|text|code|audio|video|binary`。映射：图片 png/jpg/gif/webp/bmp/svg/ico；pdf；excel xls/xlsx/csv（csv 也走 SheetJS）；音视频 mp3/wav/m4a/ogg/mp4/webm/mov；代码 js/ts/vue/json/html/css/go/py/php/sh/yaml/toml；文本 txt/md/log/ini/conf。

## 二、音视频 Range 流式端点（两构建共用一层 Handler 包装）
在 `tools/fileview` 提供 `MediaHandler(next http.Handler) http.Handler`：拦截 `GET /fileview/media?path=..&name=..&dl=0|1`，`os.Open` 后 `http.ServeContent`（自带 Range/206/Content-Type；`dl=1` 时加 `Content-Disposition: attachment` 供浏览器下载）；其它路径透传 `next`。仅允许文件、非目录，无 root 约束（与现有 [disk.go](file:///e:/test/golang-tools/tools/disk/disk.go) 整卷浏览一致，面板侧已在 [panel/server.go](file:///e:/test/golang-tools/services/panel/server.go) 登录墙之后）。

接线两处（同一函数）：
- 桌面：[main.go](file:///e:/test/golang-tools/main.go) `Assets.Handler: fileview.MediaHandler(application.AssetFileServerFS(assets))`。
- server：[main_server.go](file:///e:/test/golang-tools/main_server.go) `fileview.MediaHandler(gzipAssets(application.AssetFileServerFS(assets), assets))`（Media 响应不 gzip，ServeContent 自己处理，包在最外层即可）。

前端音视频 `<video>/<audio>` 的 `src="/fileview/media?path=..&name=.."`；大 pdf 也可用它做 iframe src。

## 三、前端页面与组件
新建 `frontend/src/views/tools/viewer/index.vue`，弹窗按 [前端弹窗规范] 拆进 `views/tools/viewer/components/`。右栏按 kind 分发到子组件：

- `components/CodePane.vue`：CodeMirror6，可编辑；顶栏「保存 / 放弃 / 只读切换」，dirty 红点；大文件或 `Binary=true` 自动只读。语言与主题按需 dynamic import（避免主包膨胀，构建已警告 >500kB）。
- `components/ImagePane.vue`：自绘查看器，`<img>` + 缩放/适应/1:1/旋转/透明底衬（沿用 [body-viewer] 的浅色底衬与 [screenshot] 的 canvas 变换思路）；src 用 `FileReadBinary` 的 dataURL，超限回退到 Media 端点。
- `components/PdfPane.vue`：`<iframe :src>`（dataURL 或 `/fileview/media`），交给 Edge/Chromium 内置 PDF 查看器，零依赖。
- `components/SheetPane.vue`：SheetJS `read` → workbook → 每个 sheet 用 `a-tabs` + `a-table` 渲染（csv 同路径）。
- `components/MediaPane.vue`：原生 `<audio controls>` / `<video controls>`，src 指向 Media 端点。
- `components/BinaryPane.vue`：`a-empty` 式信息卡（大小/类型/首尾字节 HEX）+ 两个按钮：`FileOpenSystem`（桌面）与「下载」（`window.open('/fileview/media?...&dl=1')`）。

左栏文件浏览复用磁盘能力：`DiskList` + `common-file-icon` + 面包屑 `.crumbs`（对齐 [磁盘/FTP 面包屑模式]）；点文件 → 判 kind → 渲染；地址栏支持手输/粘贴路径；`?path=` query 进入即定位（供磁盘页「在查看器中打开」跳转）。

## 六、跨平台合规（AGENTS 硬约束）
- 新 Go 全部跨平台、`CGO_ENABLED=0` 可编；`FileOpenSystem`/Media 在 Linux 语义为「浏览服务器本机文件」，系统打开失败/无 xdg-open 明确提示「当前环境无图形界面」，不吞成假成功。
- `tools/fileview` 为新增 tools 包，**必须带 `go test`**：`fileview_test.go` 覆盖 `Classify`、`ReadText`/`WriteText`（临时目录往返、二进制判定、截断、越界大小）、`ReadBinaryDataURL`、`MediaHandler`（用 `httptest` 验 200/206 Range、`dl=1` 的 Content-Disposition、目录被拒）。
- 前端按能力渲染：`FileOpenSystem` 按钮在 `caps` 无桌面能力时隐藏/禁用，不靠调用失败回退。
