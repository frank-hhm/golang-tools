## 二、「本地」勾选到底控制什么（不写清就会自相矛盾）

引导文件本身就存着绑定信息，存量代码里有二十多处直接 `os.ReadFile` 读配置，所以**本地技术上不可能真关掉**，硬去做就是回归重灾区。这一项的语义定成两条：

- **勾着本地（默认）**：本地是保存位置之一，也是权威可读源；远端只是副本。远端挂了不影响运行，只标脏，恢复后自动补齐，UI 不打扰。
- **取消本地**：本地降级为临时工作缓存（运行期照写，不改任何存量代码），但启动时**远端优先** —— 绑定可达且远端摘要与本地不同就把远端内容原子写回本地再交给各服务读；此时远端不可达就等于「这次启动没有任何受管保存位置」，触发弹窗。

不做的事（写死在代码注释里）：不把 MySQL/Redis 当配置真源去改各 store 的读写路径；不做多机冲突解决（只有本机远端优先一条规则）；不做第三方云（那是 `tools/clouddrive` 的事）；不动 `panel/settings.json`。

## 三、文档清单：扫描为主，人工知识只有三张表

`docs.go` 按 `appdirs` 的目录约定（`data/<服务名>/<文件>.json`）递归扫描（深度 2），引导文件 `app/config.json` 落用户配置目录、单独开特例。只要新服务的缓存还落在这个位置，扫描自然把它纳入 —— **不需要「加个服务就回来补一行登记表」**，展示名没登记时兜底成文件名（这条有单测守着）。

扫描之外只有三类人工知识：

- `excludedDirs`：运行时目录与版本下载缓存（`lanshare/uploads/`、`*/<name>-servers/`）——不是配置，体积也不受控。
- `excludedKeys`：`panel/settings.json` 永不外存，UI 连开关都不给。理由写在表旁：把它写到另一个进程能读的库里，等于把本机 0600 的防线换成「看谁能连上那台 MySQL」。
- `sensitiveKeys`：mysql/redis 实例登记、终端凭据、FTP 连接、云盘账号、加密空间口令 —— 默认不外存，勾选后才纳入且写入前信封加密。

单文档上限 4 MiB（`maxDocBytes`），超限不纳入并在 UI 说明原因 —— 外存走本机实例，塞几百 MB 台账只会拖垮它。

## 四、引擎：一个 goroutine、一份内存快照、一个待同步队列

`Start(emit)` 起一个 ticker（`IntervalSec`，默认 5s，上限 3600s），每轮 `scanOnce()` + `flush(false)`；`Stop()` 在退出前 `flush(true)` 硬补一次，`flushTimeout` 5s 超时就直接带未完成副本退出（下次启动照扫）。

- **脏标记**：`snap[key] = {digest,size,mtime}`，只有 digest 变了才给每个启用中的位置入队；首轮扫描把当前样子记成基线，所以不会每次启动把所有文档重写一遍远端（有单测）。
- **空队列不碰远端**：`flush` 开头 `len(pending)==0` 直接 return，一轮空转不会多打一次 Prepare（有单测）。
- **失败冷却**：位置连不上就 `failAt[kind]=now+30s`，冷却期内 `usable()` 为假、不再重复拨号，但**待同步内容保留在队列里**，不是丢掉（有单测）。
- **队列上限 200**：`dropOldestLocked()` 丢最久没动的一份并累计 `dropped` 给前端看。
- **广播去重**：`viewSignature(v)` 不变就不发 `datastore:status`，避免 5 秒一次的无效重绘把主页拖慢。
- 删除联动**故意不做**：本地文件没了就从 `snap`/`pending` 摘掉，远端那份留着 —— 宁可多留一份历史，也不把误删放大成两处一起丢。

## 五、两个位置的落库形状（都是自动建，不给用户留手动步骤）

- **MySQL**：先连不带库名的服务器（因为库还没建），`CREATE DATABASE IF NOT EXISTS <库名> CHARACTER SET utf8mb4` + `CREATE TABLE IF NOT EXISTS tools_data_store`（`data_key VARCHAR(191) PRIMARY KEY, payload LONGBLOB, digest CHAR(64), size_bytes BIGINT, encrypted TINYINT, synced_at DATETIME(3), updated_at TIMESTAMP`）。连接参数从实例登记表自取（`mysql.InstanceConnConfig(id)`），**不复用 SQL 页那套连接表**，免得外存同步和用户的 SQL 会话互相干扰。库名只接受 `[A-Za-z0-9_]{1,64}` 且不以数字开头（`config.StorageIdentOK`），因为它要拼进反引号标识符。
- **Redis**：`Tools:data:<key>` 存 payload，`Tools:data:__meta__` 一个 hash 存各键元数据；payload 不塞进 hash（大值会拖累整个 hash 的读写）。库序号 0~15 走 `SELECT`，越界回落 0。
- 两者的实例下拉**绝不回传凭据字段**，只给模式/端口/运行态；一个实例都没有时给「去新增」入口（`openToolWindow("/tools/mysql" | "/tools/redis")`，Web 模式自动退化成路由跳转）。

## 六、加密边界

勾选「含凭据的文档加密后外存」后写入的是 `enc:v1:` 信封（AES-256-GCM，数据密钥随机，主密钥的加封走既有 `tools/secret`，Windows 上是 DPAPI —— 同用户同机器才解得开）。**`meta.digest` 记的始终是明文摘要**，所以加密文档也能靠摘要判断本地与远端是否一致，恢复端解不开时明确报「主密钥换过了？」而不是静默跳过。跨机恢复从来不包括这一组文档，UI 上写明了这一点。

## 七、启动顺序与弹窗门控

`main.go` / `main_server.go` 在 `LoadAppConfig` 之后调 `datastore.Startup(storageSection)`：先按勾选建 sink → 逐个 Prepare/Metas → 摘要不同就 `writeFileAtomic` 回写本地 → 返回 `(changedConfig, note)`；若 `changedConfig` 为真，后续启动流程用远端那份配置继续（本机文件只是缓存）。一个位置都没 ready → `markFallback` 记下这次是「以本地数据运行」。

`NeedsChoice` 的口径（和前端弹窗一一对应，单测逐条覆盖）：

```go
out.NeedsChoice = !cfg.Local && !sessionLocal &&
    (anyEnabled && !anyUsable || (!anyEnabled && fallbackLocal))
```

`sessionLocal` 是「本次使用默认数据」这个临时选择，只活在当前进程，**不改设置里的勾选** —— 下次启动照旧被问一次。少了这个门控，用户明明做了选择还会被反复拦。

`Restore()` 尾部有个坑值得记：原本打算「恢复后清空整张快照」，注释写着避免「又把原样写回远端」，实际效果恰好相反 —— 快照空了下一轮扫描会把所有文档当本地新改动全量重排。现在改成**按份更新**：只把刚写回的那几份的 `snap` 换成新内容摘要，其余文档照旧拿旧快照比。

## 八、前端两块界面

**设置页「数据保存」分类**（`SETTING_TABS` 新增一项，不带 `desktopOnly`，Web 面板同样能配；`SEARCH_INDEX` 同步补 8 条，`data-skey` 一一对应）：三个位置多选 → 勾了才出现绑定区（实例下拉 + MySQL 库下拉/手填、Redis 序号）→ 状态一览表（`ssText`：未启用 / 未绑定实例 / 实例已不存在 / 实例未启动 / 连不上 / 已连通 · N 份待同步）→ 文档清单逐行可排除 → 立即同步、从远端恢复、打开本地数据目录、启动绑定实例。`testSink` **按已落盘的绑定试**，和表单不一致时提示「先点保存设置再试」，而不是替用户偷偷保存。保存走专用的 `DataStoreSaveSettings`（逐字段回写），不复用整份配置保存，避免 payload 缺段把 `exclude` 这类没渲染的字段抹掉。

**主页**（`welcome-card` 内、统计卡片上方）：`storageNotice` 提示条按 tone 上警告/错误色，带就地动作（启动 MySQL / 启动 Redis / 立即同步 / 保存位置设置）；`needsChoice` 时弹不可绕过的选择窗（`closable`、`mask-closable`、`esc-to-close` 全 false，无 footer），三个出口：启动服务、本次使用默认数据（`DataStoreSetLocalOverride(true)`）、去修改保存位置设置。数据来源是 `datastore:status` 事件 + 挂载时一次拉取 + 30 秒慢轮询（`document.hidden` 时跳过），比让主页每 5 秒去猜远端状态便宜得多。

## 九、单测在验什么

`datastore_test.go` 用 `sinkFactory` 这个注入缝把两种 sink 换成内存实现（生产路径就是 `defaultSinkFactory`），配合 `t.TempDir()` + `appdirs.Set` + 重定向 `APPDATA`/`XDG_CONFIG_HOME`（否则清单里会混进跑测试这台机器的真配置），使这些分支在**没有任何实例的机器上也能跑绿**：脏标记只标改动、空 flush 不重敲、展示名兜底、四类排除原因、含凭据勾选后必须是密文且元数据记明文摘要、连不上只标待同步并冷却、Restore 只覆盖真不同的那份且孤儿键不落盘、Startup 远端优先与勾本地时不动本地、`NeedsChoice` 全分支、队列满丢最旧。
