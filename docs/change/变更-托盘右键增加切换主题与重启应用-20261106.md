## 二、切换主题：query 与事件两条路互补

`openSettingsFromTray(tab string)` 现在带分类参数：

- 托盘「基本设置」传 `""` —— 行为与改动前**逐字节一致**（不把已经开着的设置页从用户正在编辑的分类上抢走）。
- 托盘「切换主题」传 `settingTabTheme = "theme"`，路径拼成 `/win/tools/settings?tab=theme`，仍走 `/win` 前缀的 BlankLayout 单例路由（`OpenToolWindow` 的 `single` 名会把 `?query` 剥掉，所以和「基本设置」复用同一个窗口，不会开出第二个设置页）。
- **两条路各治一种情形**（沿用工具页 `?inst=` + `tool:select-inst` 的既有手法）：
  - 新建窗口 → URL 上的 `?tab=theme` 生效，页面 `onMounted` 里落位；
  - 窗口早已开着 → 单例复用只 `Show/UnMinimise/Focus`，query 根本不会重新生效，于是再广播一条 `settings:tab` 事件让活着的实例切分类。

前端 [settings/index.vue](../../frontend/src/views/tools/settings/index.vue) 新增 `gotoTab(key)`：只认 `SETTING_TABS` 里真实存在的 key，认不出就当没这次请求（Web 模式下没有「浮动球」等 desktopOnly 分类，硬设过去会落进一个左侧导航里都不存在的空面板）。同时按本页既有写法注册/注销监听（`offSettingsTab`，`onBeforeUnmount` 里收掉）。

## 三、重启应用：拉新进程的时机放在退出收尾尾部

`restartApp()` 只做三件事：记日志、置 `restarting`、调既有的 `RealQuit()`。真正拉起新进程在 `ServiceShutdown()` **最后一行**：

```go
if a.restarting.Swap(false) { if err := restartSelf(); err != nil { ... } }
```

这个位置是核对过 Wails beta.12 的关闭次序后选的（`pkg/application/application.go` 的 shutdown 序列）：

1. 框架先注销全局热键（`GlobalShortcut.UnregisterAll`）—— 新实例不会撞热键；
2. 才调 `shutdownServices()` → 本项目的 `ServiceShutdown`，其中 `unmountArchiveHost/unmountGitHost/unmountNavigateHost` 收掉命名管道式转交端点、`BrowserCloseAll` 释放浏览器 profile 锁；
3. 上面这些做完，才是安全的交棒点 —— 若在菜单点击当下就 spawn，新实例会去抢旧实例仍占着的转交端点文件（谁先起来谁接右键/通知点击，后起来的接不到），旧实例随后 unmount 还可能把新实例的端点文件删掉，这个洞会一直留到新进程下次重启。

`Swap(false)` 保证标记只用一次；`restartSelf()` 失败只记 warn，退化成一次普通退出（不弹窗、不重试）。

**不带任何命令行参数**：重启等于一次干净的双击启动。上一次启动若是由压缩右键 / SendTo / 通知点击（`--archive`、`--archive-panel`、`tools:xxx`）拉起来的，那些转交语义不该在重启后再执行一遍。工作目录定在 exe 所在目录，与资源管理器直接双击一致。

`restartSelf()` 按平台拆两个文件（方法与 `App` 都不带 build tag，零 cgo）：

- [restart_windows.go](../../services/app/restart_windows.go)：`exec.Command(exe)` + `SysProcAttr{HideWindow, CREATE_NO_WINDOW}`。CREATE_NO_WINDOW 是必要的：发布包是 `-H windowsgui` 本就没有控制台，但 dev 构建是控制台程序，光 `HideWindow` 在 Win11 上藏不住 Windows Terminal（本机既有约定，见 `services/sysx/proc_windows.go` 同条注释）。
- [restart_other.go](../../services/app/restart_other.go)：如实回 `sysx.ErrUnsupported`。Linux 上这程序是 `-tags server` 的面板部署，进程生命周期归 systemd / docker 管，自己 fork 一个只会和托管层抢同一监听端口。

## 五、仍需人工确认与已知代价

1. **托盘三项点击**（真机）：① 设置页未开 → 新开窗直接落在「主题与外观」；② 设置页已开在别的分类 → 靠 `settings:tab` 切过去；③ 重启 → 旧进程退出、新进程出现并可用（托盘图标不残留两个）。
2. **重启会停掉本程序拉起的服务实例**：`ServiceShutdown` 无条件 `StopAll` Redis/MySQL/PHP/Nginx/npm 并断开全部终端会话，新进程不会替用户把它们再拉起来。这是既有的退出语义，重启只是让它更容易被误触发——如果接受不了，下一步该做的是「重启前列出在跑实例并二次确认」或让新实例按标记恢复上一轮在跑的实例，两者都未在本次范围内。
3. **单例复用路径里的 `w.Focus()`**（改动前就有）：beta.12 的 `chromium.Focus()` 在 `MoveFocus` 失败时会 `os.Exit(1)`。本次没扩大它的调用面（「切换主题」和「基本设置」走的是同一个函数、同一条路径），但这条风险仍在原处。
4. 快捷搜索（Alt+Space）的命令清单没有加「重启应用」——用户只点了托盘，没有要求扩展那里。
