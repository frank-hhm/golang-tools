# 变更-窗口首帧黑底治理-20261103

## 诉求

打开子 WebView2 窗口的瞬间会先亮一整块黑色，然后才出现内容。用户希望把这块黑改成
"透明玻璃"，并且明确"我们自己弄，不用 Windows 的透明"。

选型确认：**窗口照旧立刻显示 + 自绘玻璃骨架层**（不走"建窗即隐藏、首帧再显示"那条路），
取色器窗保持现状不动。

## 根因

不是页面背景，是 Go 侧建窗参数写死了近黑：

- `services/app/app.go` 的 `OpenToolWindow` → `BackgroundColour: application.NewRGB(6, 7, 15)`
- `main.go` 主窗 → 同一个 `(6, 7, 15)`

WebView2 首帧合成之前，Win32 会用这个底色擦客户区，于是亮出一整块带 Win11 圆角投影的黑板。
**它跟前端主题无关**——浅色主题下同样是一块黑。

## 时序与各自的接管区间

| 区间 | 谁在画 | 本次处理 |
| --- | --- | --- |
| 建窗 → WebView2 控制器就绪 | Win32 用 `BackgroundColour` 擦客户区，**前端一行代码都执行不了** | 底色改为按主题取，与页面底色同档 |
| HTML 开始渲染 → Vue 挂载完成 | 内联在 `index.html` 里的骨架层 | 新增，自绘玻璃质感 |
| 挂载完成之后 | 真实页面（各页自己的加载态/空态） | 骨架淡出交棒 |

必须如实说明的限制：**第一段没法用自绘玻璃接管**，因为那时 JS 与 CSS 都还没执行。
所以那一段靠"底色对齐页面底色"来消除违和，而不是靠骨架。
真要"透出背后的窗口/桌面"只有 Win32 分层透明一条路，本方案按用户要求不走。

## Go 侧改动

- `services/app/app.go`：新增跨平台 `WindowBackground() (uint8, uint8, uint8)`，
  返回 Arco `--color-bg-1` 的两档值（浅色 `255,255,255` / 暗黑 `23,23,26`，即 `#17171A`），
  正是 `BlankLayout` 的 `.blank-layout` 底色，衔接处看不出来；`OpenToolWindow` 改用它。
- `services/app/app_platform_windows.go`：新增 `windowDark()`，`light`/`dark` 直接照搬配置，
  `auto` 读注册表 `.../Themes/Personalize` 的 `AppsUseLightTheme`（0 = 深色应用模式），
  与浮动球面板的 `ballEffectiveDark` 同一口径；读不到注册表按浅色处理。
- `services/app/app_platform_other.go`：`windowDark()` 只看配置主题档（非 Windows 没有统一的
  系统深浅色事实源）。Linux 无头模式其实不建原生窗口，但底色取值在跨平台的 `app.go` 里调用，所以它必须存在。
- `main.go`：主窗底色同样改用 `application.NewRGB(appsvc.WindowBackground())`。

按 AGENTS.md 的口径，差异属于"实现不同"，走 `*_windows.go` / `*_other.go` 平台文件，
没有新增对前端暴露的绑定方法，因此**不需要重新生成绑定**。

## 前端改动

- `frontend/index.html`：新增 `#boot` 骨架层 + 内联样式 + 一小段内联主题脚本。
  - 版式对齐工具窗：一条自绘标题栏骨架 + 一组卡片骨架，带 shimmer 扫光。
  - "玻璃"是自绘质感：两束柔和高光 + 135° 细斜纹颗粒 + 骨架条扫光，浅/暗两套取值。
  - 放在 `#app` **之外**：Vue 挂载会整体替换 `#app` 的内容，写在里面会被连根拔掉。
  - 主题在打包资源之前就要定，所以用内联脚本读 `localStorage` 的 `app-theme-mode`
    （与 `utils/theme.ts` 的 `THEME_STORAGE_KEY` 同一个键），`auto` 时问 `prefers-color-scheme`。
  - **带一条 3.2s 的 CSS 自动退场兜底**：万一 JS 报错没走到淡出，骨架自己消失，绝不永久盖着页面。
  - `pointer-events: none`，骨架期间不挡点击；`prefers-reduced-motion` 下关掉扫光。
- `frontend/src/utils/boot.ts`（新增）：`dismissBootSplash()`，等两帧再淡出
  （挂载完成那一帧页面还没真正画出来，立刻撤只是把裸底色换成空白页），
  再兜一次 400ms 定时清理，防页面被后台节流时 `transitionend` 不来。
- `frontend/src/main.ts`：`app.mount()` + `initTheme()` 之后调用 `dismissBootSplash()`。
  顺序要紧：主题落定后再撤骨架，否则会出现"浅色骨架淡出 → 露出没换肤的页面"这一跳。

## 验证到哪一层

- `go vet ./services/...` 与 `go vet .` 均 0。
- 三构建全部 0 退出码：`go build .`（Windows 桌面）、`go build -tags server`（Windows Web）、
  `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -tags server`（Linux 面板）。
- `node scripts/build.mjs`（`vue-tsc --noEmit` + `vite build`）通过，
  并核对过 `dist/index.html` 里骨架层的 DOM、内联 CSS（`bootShine`）、内联主题脚本
  （`app-theme-mode`）三者都被 vite 完整保留、没被提取走。
- `gofmt -l services main.go` 未列出本次改动的任何文件。
  （该命令会列出仓库里既有的 28 个未格式化文件，本次没碰它们。）
- **没有做真机端到端复验**：黑底是否真的消失、骨架淡出的节奏是否合适，
  需要重启应用开几个工具窗看实际效果。Linux 侧只有编译级验证，没有 Linux 环境。

## 部署提醒

`frontend/dist` 不入库。服务器上要看新行为，必须先 `cd frontend && npm run build` 再重新构建二进制。
本次校验产物 `bin/_v_linux.exe`、`bin/_v_winserver.exe` 需手动清理。
