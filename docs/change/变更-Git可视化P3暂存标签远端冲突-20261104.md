## 一、引擎层 tools/gitcmd（LF，纯 Go 零 cgo）

- **p3a 暂存栈**（`stash.go` 新建 + `gitcmd.go` 加 `StashEntry`）：`StashList`（`git stash list --format=%gd%x09%gs%x09%ci`，从 `stash@{N}` 取序号）、`StashPush(msg, includeUntracked)`（`git stash push [--include-untracked] [-m msg]`）、`StashApply/Pop/Drop(ref)`。`stashRef` 把纯数字选择器补成 `stash@{N}`、空串兜栈顶；因走 argv 不构成注入。git 对「无改动可暂存」退出码 0 只提示 stdout，翻成 `ErrNothingToStash` 让人话可提示。
- **p3b 标签**（`tag.go` 新建 + `Tag` 类型）：`TagList`（`for-each-ref refs/tags`，字段模板含 `%(*objectname:short)` 剥离附注标签指向的提交）、`TagCreate(name, message, target)`（message 非空 `-a -m` 建附注、空建轻量）、`TagDelete`。**关于签名**：本包不碰私钥/口令，而 `tag.gpgSign=true` 的仓库在建附注标签时会调 gpg 弹 pinentry，无头子进程直接挂死——故 `TagCreate` 一律注入 `-c tag.gpgSign=false`，即**拒绝产出签名附注标签**（与包注释「凭据交系统」一致，需签名回命令行）。
- **p3c 远端**（`remote.go` 新建 + `Remote` 类型）：`RemoteList`（`git remote` 拿全集 + `git remote -v` 填 fetch/push 地址，正则解析）、`RemoteAdd/Remove/SetURL(name, url, push)`（push=true 走 `--push`）。
- **p3d 冲突三方 + rebase**（`conflict.go` 新建 + `ConflictSides`/`OpState` 类型）：`Conflicts`（`diff --name-only --diff-filter=U`）、`ConflictSidesOf(path)`（`ls-files -u` 按 stage 1/2/3 取 blob 号，`git cat-file blob` 取原始内容；缺失槽回空串）、`ResolveConflict(path, side)`（`side` 走 `ours|theirs` **白名单**，非法值直接报错防注入额外旗标；`checkout --ours/--theirs` 后 `git add` 标记已解决）、`MarkResolved(path)`（`git add`）、`OpStateOf`（`rev-parse --absolute-git-dir` + `os.Stat` 探测 `MERGE_HEAD`/`CHERRY_PICK_HEAD`/`REVERT_HEAD`/`BISECT_LOG`/`rebase-merge|rebase-apply`）、`RebaseContinue`（注入 `-c core.editor=true` 顶掉编辑器防卡死，与 Revert 的 `--no-edit` 同考量）、`RebaseAbort`。
  - 注释明确记录了 rebase 语境下 ours/theirs 语义与 merge 相反，供前端文案区分。
- **单测**（`p3_test.go` 新建）：`TestStashE2E`（含 `--include-untracked` 收走未跟踪文件、apply 保留/pop 出栈、无改动→ErrNothingToStash、drop；断言前对 CRLF 工作区归一化，并处理 apply/pop 连续操作需先清工作区的 git 行为）、`TestTagE2E`（轻量 vs 附注、剥离 commit、subject、删除）、`TestRemoteE2E`（增/列/改 fetch/单设 push/删）、`TestConflictResolveE2E`（分叉 merge 造冲突 → OpStateOf.Merge、三方内容 base/ours/theirs 精确断言、选 ours 覆写并出冲突表、非法 side 被白名单挡）、`TestRebaseE2E`（rebase 造冲突 → OpStateOf.Rebase、abort 回退、再 rebase 选 theirs + continue 完成）。真 git 端到端，无 git 则 `t.Skip`。

## 三、前端 views/tools/git/components

- **`StashModal.vue`（新）**：栈列表（# / 说明 / 时间）+ 暂存表单（说明输入 + 「含未跟踪」勾选，tooltip 明确「未跟踪文件会被带走、工作区消失」）+ 每行 应用/弹栈/丢弃（丢弃 `Modal.warning` 二次确认）。操作后 `emit('changed')` 刷父页状态。
- **`TagModal.vue`（新）**：列表（标签 / 类型[附注|轻量] / 提交 / 说明）+ 创建表单（名 / 起点[空=HEAD] / 说明[空=轻量]）+ 删除（二次确认，注明仅删本地）。顶部 note 说明「附注标签一律不带 GPG 签名，需签名回命令行」。
- **`RemoteModal.vue`（新）**：列表（名 / 抓取 / 推送）+ 添加（名 / URL）+ 改地址（**行内编辑**，避开 webview 里不可靠的 `window.prompt`，只改 fetch）+ 删除（二次确认，说明本地失去 remote 与追踪引用）。
- **`ConflictModal.vue`（新）**：左列冲突文件、右列三方（基线 / 我方 / 对方三栏 `<pre>`），每栏「采用我方/对方」走 `GitResolveConflict`（选边即覆写并标记解决）；「手动编辑…」嵌入 **复用 `DiffPane`**（工作区侧含冲突标记、可编辑、`FileWriteText` 保存，`defineAsyncComponent` 挂），保存后「标记已解决」走 `GitMarkResolved`。顶栏按 `OpState` 显示 变基/合并/拣选/回退 进行中徽标；rebase 态额外给「继续变基」(无冲突才可点)/「放弃变基」(二次确认)。rebase 语境下栏头文案切换为「我方(上游)/对方(重放提交)」并给橙色警示。全部结束/破坏操作后 `emit('changed')`。
- **`index.vue`**：head-bar 加「工具」下拉（暂存栈/标签/远端）与冲突时现身的「解决冲突N」红按钮；变更区冲突分组改为每行「解决」入口 + 顶部按钮打开 ConflictModal；挂载四个弹窗（`@changed="refreshStatus"`）；新增 `stashVisible/tagVisible/remoteVisible/conflictVisible` + `onTools/openConflict`。
