## 一、引擎层 tools/gitcmd（LF，纯 Go 零 cgo）

- **p2a 冲突态重路径去重**（`diff.go`）：`parseNumstat` 改为按 `path` 合并（`idx map`），同一路径多 stage 行取各阶段最大增删、任一为二进制即整体标二进制。修计划 §十四 记的「冲突态 `Files()` 把同路径返回两次、前端以 path 为 v-for key 撞车」缺陷。
- **p2b 单文件历史 --follow**（`log.go`）：`Log` 签名由 `Log(ctx, repo, limit)` 改为 `Log(ctx, repo, revision, path string, limit)`；`path` 非空追加 `--follow`（git 要求 --follow 仅配单路径），`revision`/`path` 作位置参数拼接。
- **p2c blame 解析**（`blame.go` 新建 + `gitcmd.go` 加 `BlameSegment` 类型）：`Blame(ctx, repo, path, revision)` 跑 `git blame --line-porcelain [rev] -- path`，`parseBlame` 用 `blameHeadRe` 认块首行、把连续同 hash 的行聚成段（author/author-time/summary 各取一次，StartLine 用最终行号）。
- **p2d 历史节点变更操作**（`ops.go`）：新增 `CreateBranchAt(name, startRef, checkout)`、`CherryPick(hash)`（`--empty=drop`）、`Revert(hash)`（`--no-edit`）、`Reset(mode, target)`——`mode` 走 `soft|mixed|hard` **白名单**（非法值直接报错，防注入额外旗标），空 target 兜 HEAD。
- **并排差异取全文**（`diff.go`）：新增 `ShowBlob(ctx, repo, rev, path)` 跑 `git show <rev>:<path>`；`rev==""` 即 `:path`（暂存区 index）；该版本无此文件（新增文件的父、删除文件的当前、首提交的父）经 `missingBlob` 判定回空串而非报错，前端据此一侧渲染空、另一侧全增/全删。
- **单测**（`gitcmd_test.go`）：新增 `TestParseBlame`（聚合分段）、`TestParseNumstatConflict`（同路径合并取最大）、`TestLogFollowE2E`（纯 `git mv` 100% 相似 → --follow 回溯改名前提交）、`TestHistoryOpsE2E`（建分支/cherry-pick/revert/reset soft+hard/非法 mode 拦截/游离检出/blame）、`TestShowBlobE2E`（HEAD/index/首提交父不存在→空）；既有 `Log(ctx,dir,limit)` 调用点随签名更新。真 git 端到端，无 git 则 `t.Skip`。

## 三、前端 views/tools/git/components

- **装 `@codemirror/merge@6.12.3`**（yarn，用 `D:\nvm\v22.23.2` 跑避开 nanoid@6 引擎门槛）。
- **`DiffPane.vue`（新）**：`@codemirror/merge` 三态——并排（`new MergeView({a:基线只读, b:当前})`）、内联（`unifiedMergeView({original, mergeControls:false})`）、补丁兜底（`GitDiffText`）；`MergeView`/`unifiedMergeView` 走 **dynamic import**（计划要求，独立 chunk 不拖累主包）。左右全文来自 `GitShowBlob` +（工作区侧）`FileReadText`；工作区改动侧**可编辑并保存走 `FileWriteText`**（截断/二进制锁只读，与查看器 CodePane 同安全口径），NUL 判二进制退化。CodeMirror 基础件与 CodePane 同源（basicSetup + oneDark + 按扩展名动态语言包）。
- **`DiffModal.vue`（重写为外壳）**：a-modal 只留可见性 + repo/opts，`defineAsyncComponent` 挂 DiffPane，编辑器/模式/保存全部下沉 DiffPane 自管（遵循「父只给上下文」弹窗规范）。
- **`HistoryPane.vue`（重写为 canvas DAG + 虚拟滚动）**：固定行高 `ROW_H=30`，只渲染视口内行（上下各 BUFFER 行）；`<canvas>` 绝对覆盖最左图区、DPR 缩放，按引擎给的 `lane`+`parents` 为可见行画节点圆点与到父节点的连线（同列直线、跨列二次贝塞尔）；`ResizeObserver` 测高、`onScroll` 重绘。`--follow` 入口：文件行「历史」按钮 → `followPath` 非空时 `GitLog(repo,'',path,0)` 进单文件历史，顶栏「返回全历史」退出。变更操作 UI：选中提交详情头部 a-dropdown——检出此提交 / 在此建分支（弹输入框 `GitCreateBranchAt(...,startRef=hash,checkout=true)`）/ cherry-pick / revert / reset soft·mixed·hard；`reset hard` 先 `GitStatus` 数出将丢的改动项数，`Modal.confirm` 危险态二次确认；操作成功 `emit('changed')` + 重载历史。
- **`BlamePane.vue`（新）+ `BlameModal.vue`（外壳）**：`GitBlame(repo, path, revision)` 取段，读正文（`FileReadText`）按行号对齐，段首显示「作者·相对时间·短哈希·summary」、段内其它行按需补哈希，按 hash 稳定配色。入口：历史详情文件行「追溯」。
- **`index.vue`**：`<history-pane>` 接 `@blame`/`@changed`（后者 `refreshStatus`）；`<diff-modal @saved>` 保存后刷状态；挂 `<blame-modal>`；新增 `openBlame`/`onHistChanged`。
