## 诉求

做一个「多主题」系统：把主色、圆角、密度、高对比度、减少动效这些观感维度做成一套**与 light/dark 正交的设计令牌**，
通过预设皮肤 + 自定义取色即可整体换肤，且**不大规模改存量页面**；「透明」先在隔离实验台验证表面磨砂观感，定样式后再决定是否铺全局。

## 决策基线（已确认）

- **组件策略**：L0 全局皮肤（主题 scss 覆盖 `.arco-*`）+ L1 薄封装（AppCard/AppModal，阶段二引入）。本轮不动存量页面。
- **传导路径**：全站页面几乎都读 `--primary-6` / `--color-*` / `--base-radius-*` / `--base-size-*`，
  把这些变量在 `documentElement.style`（inline）覆盖，即自动传导全站，零页面改动。这是「整套令牌正交明暗」能落地的关键。
- **持久化双轨**：前端 localStorage 即时（无闪烁、跨窗口 `storage` 事件同步）+ 后端 `config.general.theme`（对象，首次运行/新窗口回退）。
- **透明**：本轮只做表面磨砂（CSS `backdrop-filter`，跨平台安全），隔离在实验台页；窗口级 DWM Acrylic/Mica 曾因与无边框冲突致「灰纱/白跳」整体下线（见 `变更-透明模式整体下线-20261103.md`），本轮不自建 translucent 窗链路，绝不阶段一推广。

## 后端改动（`services/config`）

- `GeneralConfig.Theme` 由 `string` 改为 `ThemeConfig` 结构：`Mode/Preset/Primary/Radius/Density/Contrast/Motion/Glass`，均带 json tag。后端**只持久化不消费**（除 mode 外）。
- **向后兼容**：`ThemeConfig.UnmarshalJSON` 容忍旧裸字符串 `"theme":"light"`——按 mode 解析并补默认其余维度；`null`/空 → 零值由归一化兜默认；对象正常解码（`type alias` 规避递归）。老配置无需迁移脚本。
- `defaultThemeConfig()` = `{light, default, default radius, standard density, normal contrast, on motion, off glass}`；`normalizeThemeConfig()` 逐维度兜默认并校验枚举合法性。
- mode 消费点全改为 `.Theme.Mode`：`SaveAppTheme`、`app.go` 的 `BallTheme`、`app_platform_windows.go` / `app_platform_other.go` 的 `windowDark`。
- 新增 `services/config/config_theme_test.go`：旧字符串兼容、对象全字段、null、Marshal 往返、归一化、完整配置里嵌旧值 6 组用例。
- 平台差异无（纯数据、跨平台），对前端暴露的绑定方法未增删；但结构变了，**重生成绑定**：`wails3 generate bindings -ts -i`（v3.0.0-beta.12，增量，不带 `-clean`），得到 `config/models.ts` 的 `ThemeConfig` 接口 8 字段 + `"theme": ThemeConfig`。

## 修订 2026-11-04：配色改为自建 OKLCH 多色协调体系

上线的阶段一把主色按 **Arco 的 `--primary-1..10` 线性混白/混黑** 生成十档。用户要求
“不用 Arco 的 1-10 方式，要有我们自己的搭配方式”，并选择：配色落点=**自建 `--app-*` 语义令牌为唯一真源**，
搭配产物=**多色协调主题**。本次修订据此重做配色层，**不改变与 light/dark 正交的体系与“存量页零改动”传导机制**。

### 新的搭配方式（设计口径）
- **色彩空间 OKLCH**（感知均匀，非线性混白/混黑）：新增 `frontend/src/utils/color.ts`（sRGB↔linear↔OKLab↔OKLCH
  互转 + 二分降 chroma 的 gamut-map，保 L/H 不串色不溢出）。
- **色阶**：`palette.ts` 重写。以种子为第 6 档基准，按固定明度曲线生成 10 档（light 1 最浅→10 最深、dark 反转），
  chroma 按高斯向两端收敛（不发灰也不刺眼）。10 档是为了兼容 Arco sink 的位数，生成算法完全是我们的。
- **多色和谐**：从种子色相按模式产出 brand/accent/secondary 三组色阶——`analogous(±30)`/`complementary(180,210)`/
  `split(150,210)`/`triadic(120,240)`；默认 `analogous` 保证克制不发花。
- **染色中性**：neutral 阶取种子色相 + 极低饱和（0.012），背景/文字/边框带主题色温。
- **语义色**：success/warning/danger/info 用固定 OKLCH 色相区间（145/85/25/255°），明度走同一曲线、随明暗微调。

### 令牌层与兼容投影
- `theme.ts` 投射改为两步：①`buildTheme(seed,harmony,scheme)` 算整套，写 `--app-brand/accent/secondary/neutral-1..10`
  与 `--app-success/warning/danger/info`、`--app-brand/accent/secondary`（hex，真源）；②**兼容出口**：把 brand
  转逗号 RGB 三元组写进 Arco `--primary-1..10`——因此 138+ 存量页/浮层仍零改动跟随（纯 `--app-*` 化随铺量推进）。
- `tokens.scss` `:root` 新增 `--app-*` 基准/语义静态兜底（墨蓝默认主题）；`presets.ts` 每套改为 {seed, harmony}，
  `resolveTheme` 统一预设/自定义两来源。

### 后端与设置页
- `ThemeConfig` 新增 `Harmony string`（json `harmony`）+ `defaultThemeHarmony="analogous"` + `validThemeHarmony` 枚举校验；
  `normalizeThemeConfig` 非法 harmony 回退 analogous。向后兼容不变（旧裸字符串/旧对象无 harmony 字段均合法）。绑定重生成
  `wails3 generate bindings -ts -i`（不带 -clean，v3.0.0-beta.12，3 Services/691 Methods/244 Models）。
- 设置页主题区：「主题皮肤」改「主题种子色」（swatch 读 `p.seed`）+ 新增「搭配方式（色彩和谐）」radio
  + 新增「配色预览」实时展示 brand/accent/secondary；SEARCH_INDEX 条目改为「主题搭配」。

### 透明（阶段 0 收尾）
- 实验台页保留；全局管道就绪：`tokens.scss` 新增 `body.app-glass` 下的表面磨砂规则（`.arco-card/.arco-modal/.arco-drawer`，
  浅/暗两套底色 + 减少动效时禁用模糊），**默认 `glass:"off"` 零视觉变化**。取值 alpha=0.72/blur=16px/border=0.3 为临时设计值，
  **待用户在实验台肉眼定稿后改这三枚即可**；窗口级原生透明仍不碰。

### 修订验证到哪一层
- `node scripts/build.mjs`（vue-tsc + vite，Node 24）通过；palette/color 单测 8/8 通过（往返、明度单调、和谐色相偏移、染色中性低饱和、harmony 合法化）。
- `gofmt -l` 无输出、`go vet ./services/config/... ./services/app/...` = 0、`go test ./services/config/... -count=1` ok（含 harmony 兼容与归一断言）。
- 三构建全 0：`go build .` / `go build -tags server .` / `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -tags server`（已验产物为 ELF，`\x7fELF`）。`bin/` 临时产物已清理。
- **未做**浏览器端到端复验：换预设/选种子/切和谐模式的实际观感、accent/secondary 在真页可读性、磨砂定稿——均需重启实测。**无 Linux 真机环境**。
