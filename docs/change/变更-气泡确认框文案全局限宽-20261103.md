# 变更-气泡确认框文案全局限宽-20261103

## 诉求

`views/tools/docker/components/ContainerLogModal.vue:18` 那句「确定清空容器日志？将只保留
清空之后新产生的日志（Docker Desktop 下容器历史日志无法从本地截断）。」把确认气泡拉成一条
横向超长文本。要求换行或限宽，并且**全局优化**：所有 `a-popconfirm` 的文案都设最大宽度。

## 根因

Arco 的 popconfirm 气泡宽度完全由内容决定：`.arco-popconfirm-body` 是 flex（图标 + 文案两列），
文案那个 `.arco-popconfirm-content` 没有 `min-width: 0`，气泡本身也没有宽度上限，
所以一句长说明就把气泡顶到窗口边。Arco 自带的只有 `word-wrap: break-word`，
没有上限时它永远用不上。

## 改动

新增 `frontend/src/styles/popconfirm.scss`，并在 `styles/index.scss` 里 `@use` 进来：

- `.arco-popconfirm-popup-content .arco-popconfirm-body { max-width: 320px }`
- `.arco-popconfirm-content`：`min-width: 0` + `white-space: normal` + `overflow-wrap: anywhere`
  + `line-height: 1.6`（长路径 / 无空格英文按词断行，不溢出气泡）

只压文案那一列，图标与按钮行不受影响。

**为什么写在全局而不是组件里**：气泡是 teleport 到 `body` 下渲染的，组件的 scoped 样式
哪怕加 `:deep` 也到不了它，跟 `modal.scss` 处理 `a-modal` 是同一个理由。

**为什么敢全站生效**：数过全项目 34 个文件用到 `a-popconfirm`，全部走 `content="字符串"`
传文案，没有一处用 `#content` 插槽塞自定义宽内容，所以限宽不会挤坏任何东西。
以后新增 popconfirm 也不需要再单独处理文案宽度。

## 验证到哪一层

- `node scripts/build.mjs`（`vue-tsc --noEmit` + `vite build`）通过。
- 在产物里核对过规则确实落地：`dist/assets/index-*.css` 中存在
  `.arco-popconfirm-body{max-width:320px}` 与配套的 `.arco-popconfirm-content` 规则。
- `go build .` 退出码 0（新 dist 已 embed）。
- **没有做浏览器端到端复验**：320px 这个上限合不合适、换行后的行距观感，需要实际点开几个确认框看。

## 部署提醒

`frontend/dist` 不入库，服务器上要先 `cd frontend && npm run build` 再重新构建二进制。
