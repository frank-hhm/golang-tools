## 二、#2 接收进度可看（任务中心一行 + 页内 live）

- **`frontend/src/components/layouts/BlankLayout.vue`**（独立工具窗布局）：引入并渲染全局 `<task-hub />` 浮标（自带 `ensureTasks()` 订阅 `task:update`）。此前 `<task-hub>` 只挂在主窗口 `layouts/index.vue`，独立互传窗看不到跨页接收进度——这是本次前端消费缺口。lanshare 接收上传的 Task 由后端既有链路（`lanshare:progress`→`tasks.Observe`→`task:update`，tool=局域网互传）产出，无需改后端。
- **`views/tools/lanshare/index.vue`**：`lanshare:progress` 事件处理从"每事件全量扫盘 refreshGrants/Links/Inbox/Sessions"改为**按 payload 驱动**：上传进行中用事件里的 `percent` 就地刷对应 `id` 行（未知 id 才扫一次拉准确行）；仅终态（done/error/canceled）刷 `sessions/inbox/status`；`download` 只刷 `grants/links` 计数。降低高频空扫，live 百分比更跟手。

## 三、#3 关闭 webview 服务不关闭

- **根因（读码证实，`wails v3.0.0-beta.12`）**：工具窗（`OpenToolWindow` single:true）自绘标题栏"关闭"→ `Window.Close()` → WM_CLOSE → 无 `WindowClosing` 拦截则默认处理器销毁窗口 → `application_windows.go:343 unregisterWindow`：**当 windowMap 为空且未设 `Windows.DisableQuitOnLastWindowClosed`（默认 false）时 `PostQuitMessage(0)`** → 进程退出 → 跑在 Go 侧的 lanshare 端口随进程死。lanshare 服务本身与窗口生命周期无耦合（无"关窗即停"代码），停服务实为进程被连带退出。
- **修复 `main.go`**：`application.Options.Windows` 设 **`DisableQuitOnLastWindowClosed: true`**——关闭任意/全部窗口都不再自动退出进程，托盘与常驻服务存活；真正退出只走 `RealQuit`（托盘"退出"）。不改工具窗"关闭即销毁 webview"的既有语义，仅把进程生命周期与窗口生命周期解耦。
