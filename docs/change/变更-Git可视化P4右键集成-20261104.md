## 一、挂载层 tools/gitcmd（新增，注册表码按 build tag 分开）

- **`shell.go`（LF，无 tag，三平台共用）**：verb 命名前缀 `ToolsGit`；五个操作项 `gitVerbs`（Status/Commit/Push/Pull/Branch，各带 `--git-*` 标记与菜单文案 `Git (Tools) · …`）；三类宿主位置 `gitShellLocations`（`Directory`→`%1`、`*`→`%1`、`Directory\Background`→无 token 靠 cwd）；`GitShellInfo`（聚合单个 `Slot` + `MountedKeys`/`ProblemKeys`/`Stale`/`Detail`）；槽位常量与 `SlotText`/`worstSlot`/`gitDetail`（与压缩同口径）；`OpForArg`/`ParseShellArgs`（只认精确标记，认不出压缩/面板标记）、`ResolveRepo(ctx,dir)`（复用 `Discover` 的 `rev-parse`，返回仓库根与是否命中）。
- **`shell_windows.go`（`//go:build windows`）**：`GitShellStatus`（逐 verb×位置 `gitReadSlot` 聚合最差）、`GitShellInstall`（幂等，顺带修挪过位置的旧路径）、`GitShellUninstall`（只按 `ToolsGit*` 名删）。`gitWriteVerb` 写 `MUIVerb`+`Icon`+子键 `command`；`gitReadSlot`/`gitPathRefersTo`/`gitRemoveVerbTree`/`gitSelfExe`/`gitCommandLine` 与压缩同构但全用 `git` 前缀避免与 archive 包符号混淆。**Git 不挂 SendTo**（计划未要求，也更少占位）。
- **`shell_other.go`（`//go:build !windows`）**：`GitShellStatus/Install/Uninstall` 一律回 `sysx.ErrUnsupported`，上层按 Capabilities 整块隐藏挂载区。
- **单测 `shell_test.go`（新）**：`TestParseShellArgs`（命中/无 token/后续标记不误吞/压缩与面板标记不误认/普通启动/空路径）、`TestOpForArg`（五标记映射齐整 + 拒 `--archive`/`--extract`/`--archive-panel`）、`TestWorstSlot`（含未挂→absent、含读不出→damaged 优先于指错）。纯逻辑、不碰注册表、不需 git，三平台可跑。

## 二、转交层 services/githost（新，薄封装）

- 复用 `services/singleinstance`（回环 TCP + 令牌 + 端点文件），服务名 `git`（端点落 `data/git/endpoint.json`，与 `archive` 各自独立、互不覆盖）。`Request{Op,Repo,From}` + `Start(onReq)`/`TrySend(job)`。与 archivehost 同构。

## 三、宿主接线 services/app/git_shell.go（新，LF，无 build tag）

- **分流**：`GitCLICommand(args)` 转调 `gitcmd.ParseShellArgs`。`HandleGitCLI(op,repo)`：① `ResolveRepo` 不在仓库 → 同步 toast 说明并返回 true（进程退出，**上下文判断在程序内做、不改菜单可见性**）；② 命中 → `AddRepo` 登记（去重）；③ `githost.TrySend` 转交在跑实例，成功返回 true；④ 无实例 → `SetPendingGit` + `SetPendingNavigate("/tools/git")`，返回 false 让本进程正常起 GUI。
- **转交回调**：`gitHandoffOpen(op,repo)` = 拉前台 + `EmitEvent("app:navigate","/tools/git")`（复用既有导航）+ `EmitEvent("git:open",{op,repo})`。
- **开关即时生效**：`applyGitOnStart`（`!GitShellEnabled` 直接 return；开着才 `mountGitHost` + `go syncGitShell`）、`applyGitSwitch`（开→挂+起监听，关→停监听+`go unmountGitShell`）、`mountGitHost`（仅 `NativeWindows`，端点被占只记日志）、`unmountGitHost`（幂等）、`syncGitShell`（ErrUnsupported 只留日志）、`unmountGitShell`（三槽皆 absent 不写）。
- **绑定方法（跨平台存在）**：`GitShellStatus/GitShellInstall/GitShellUninstall`（转调引擎、ErrUnsupported 走日志）、`SetPendingGit/GetPendingGit`（冷启动消费一次）。

## 四、配置 services/config/config.go（CRLF，仅精确改）

- 新增 `GitConfig{ ShellEnabled bool json:"shellEnabled" }` + `AppConfig.Git *GitConfig json:"git,omitempty"`（指针：老配置读回 nil、序列化省略，不污染用户手写配置）+ `defaultGitConfig()`（**默认关**）+ `GitSection/GitCfg/GitShellEnabled` 访问器 + 默认表登记 + 配置载入 `if loaded.Git != nil` 合并。语义与 `ArchiveConfig.Enabled` 同构。

## 五、接线 main.go / app.go（CRLF，仅精确改）

- `main.go`：压缩分流之后加 Git 分流——`if op,repo,ok := appsvc.GitCLICommand(os.Args); ok { if appInstance.HandleGitCLI(op,repo) { os.Exit(0) } }`；只认 `--git-*`，普通双击与压缩链路零影响，故不必开 SingleInstance。
- `app.go`：`ServiceStartup` 加 `a.applyGitOnStart()`；shutdown 加 `a.unmountGitHost()`；配置落盘处加 `a.applyGitSwitch()`。

## 六、前端

- **`views/tools/git/index.vue`**：`onMounted` 消费 `GetPendingGit`（JSON→`applyGitOpen`）并监听 `git:open` 事件；`applyGitOpen({op,repo})` = 刷新列表 + `openRepo(repo)`，`op==='branch'` 顺带打开分支弹窗。**不盲跑网络操作**（push/pull/commit 只定位到工作台，仍由用户当场确认），与计划「开工具页定位到该仓库」口径一致。
- **`views/tools/settings/index.vue`**：仿压缩段加「Git 右键」设置卡（`desktopOnly`）——总开关 `git.shellEnabled`（`onGitEnabled` 落盘+回读+提示）、聚合挂载三态 `slotText(gitShell.slot)`、安装/修复·卸载按钮（卸载提示只删自家 ToolsGit*）、`GitCfg`/`GitShellInfo` 接口 + `normGit` + `loadGitInfo`（tab 切入时懒加载）；save payload 带 `git` 段。
- 绑定经 `wails3 generate bindings -ts`（CLI v3.0.0-beta.12 与 go.mod 一致）重生成：`app.ts` 含 `GitShellStatus/Install/Uninstall/GetPendingGit`，`tools/gitcmd/models.ts` 含 `GitShellInfo`。
