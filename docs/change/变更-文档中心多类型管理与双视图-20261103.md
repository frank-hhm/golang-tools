## 诉求

优化、美化文档面板，做到"真正的文档管理"——原来页面只有"分类树 + 一张平表"，
看不出条目是什么类型、多大、实体还在不在，操作也全铺在行末一长串链接上。

## 后端：把"类型/大小/实体时间"变成一等公民

- **`tools/filekind`（新包）**：扩展名 → kind（image/audio/video/pdf/doc/sheet/text/code/archive/binary）
  的判定从 `tools/fileview` 里下沉成独立包，`fileview.Classify` 转调它；新增 `Thumbable`/`Ext`/`KindLabel`。
  单独成包是因为 docspace 与 fileview 都要用，让 docspace 依赖 fileview 会绕出一堆无关依赖。
- **`tools/docspace/meta.go`**：`ItemMeta{ID,Kind,Mime,Ext,Size,ModTime,Unreachable,Thumbable,Thumb}`，
  每次经 `docref` 现取（派生事实不落盘，落盘就与磁盘脱节）；带 TTL 缓存与并发合批；
  `Stats`/`KindBreakdown` 在同一份元数据上汇总。`Unreachable` 为真表示实体取不到
  （已删除 / 远端会话已关），此时 Size/ModTime 一律 0，前端显「实体缺失」而不是 0 字节。
- **`tools/fileview/thumb.go`**：`/fileview/thumb?src=&sid=&path=&w=` 跨源缩略图端点
  （本机/SFTP/WebDAV/云盘都能出图），带磁盘缓存，非图片返回 415。
- **`tools/docspace/batch.go`**：`MoveItemsCategory`（分类存在性校验、`changed==0` 不写盘）、
  `TagItems`（并集加 / 差集删，无变化不刷 `UpdatedAt`）、`RemoveItems`（失败回滚内存）、
  `TrashItems`/`SnapshotItems`（逐条委托单条实现，`BatchResult` 收集失败项与首条原因）、
  `SetItemCategory`、`Overview`（分类含子级滚加、源分布、TopExts，带 visited 兜环）。
  批量方法不能持 `s.mu` 再委托单条方法——单条内部自持锁，会自死锁，所以一律"逐条走公开入口"。
- **`services/app/docspace.go`**：新增 9 个绑定
  `DocSpaceSetItemCategory/Metas/Overview/ThumbURL/MoveItemsCategory/TagItems/RemoveItems/TrashItems/SnapshotItems`，
  **全部不带 build tag**（Linux 面板同样可用）。`DocSpaceMetas` 顺手把 `Thumb` 拼好：
  网格视图几百张图逐条求 URL 就是几百次往返。`ItemMeta` 里没有 src/sid/path 三元组，
  所以再取一次 `Items()` 按下标 zip，并逐位校验 `metas[i].ID == items[i].ID`，
  并发增删导致错行时宁可不给图——错行拼出的是"别人的缩略图"，比不给图更难发现。
- 绑定已重生成（`wails3 generate bindings -clean=true -ts -i`，352 packages / 659 methods）。

## 前端：双视图 + 类型维度 + 批量

- **`useDocMeta.ts`**：`Metas`/`Overview` 一次取回，按 **id**（不是下标）拼回 `DocRow`；
  `kindColor`/`srcLabel`/`sortRows`/`rowOps`。`rowOps` 是网格卡与表格行共用的唯一一份"能做什么"，
  避免两处各维一份而漂移。排序规则：名称按中文自然序（数字 2 排在 10 前），
  体积/时间取不到的行**永远排末尾**——它们不是"最小"而是"不知道"。
- **拆组件**：`StatsBar`（5 张指标卡，数字全来自后端 Overview）、`KindChips`（类型筛选，
  计数用全量口径而不是筛选结果，否则"越点越少"）、`DocGrid`（缩略图卡片墙）、
  `DocTable`（列：名称/类型/大小/更新时间/标签/源/版本/路径/操作）、`BatchBar`（有选中才出现）。
- **`index.vue`**：网格/表格切换、类型 chips、只看缺失、排序下拉、网格分页、多选批量
  （改分类 / 标签 / 存快照 / 复制清单 / 回收站 / 移出），顶部主操作只留 3 个按钮，
  回收站/加密库/备份/高级搜索/刷新收进「更多」。左树徽标改吃 `Overview.categories[].inclusive`
  （含子级），与右列表同一口径；元数据没取到时退回本地数一遍。
- **实体缺失**的表达：卡片压暗 + 名称划线 +「实体缺失」角标，表格同理；
  批量条提前说明"其中 N 项会逐条失败"。

## 实机复验中改掉的问题（一轮造数据 → 取证 → 修复 → 复验）

1. **表格点列排序升降序结果完全一样**：Arco 传了自定义 `sorter` 后**不会**再按方向反序
   （`table.js` 直接把 sorter 返回值当结果，direction 只作为第 3 参传进来）。
   改为 sorter 自己乘方向，并保持"取不到的值不参与比较、恒排末尾"。
2. **破坏性菜单项与普通项同色**：这一版 Arco 的 `a-doption status` 只认 `normal|danger`，
   且 dropdown 样式表里没有任何 status 配色规则（实测 9553 条 CSS 规则里 0 条命中）。
   改为在下拉项内容里自己包 span 上 `ds-op-danger` / `ds-op-warn`（全局样式，
   弹层 teleport 到 body，scoped 罩不到）。
3. **48×48 的小图被 `object-fit: cover` 放大到 190×116 发虚**：`@load` 里按 naturalWidth/Height
   判断，不够盖满框的图退成 `object-fit: none` 原尺寸居中——宁可不填满，也不把图搞模糊。
4. **窗口窄于 ~188px 下限时右栏被顶出横向滚动条**：`minmax(188px,1fr)` → `minmax(min(188px,100%),1fr)`。
5. 卡片左上复选框的勾 svg 按 1em 取号、继承卡片 12px 字号后顶出 14px 方框（scrollWidth 19 > 14），按容器锁死。
6. 指标卡明细行在窄窗被省略号截断 → 每卡补 `tip`，完整口径（含"近 7 天动过"包含登记时间）放 tooltip。
7. 玻璃态（`glass.scss`）：网格卡换玻璃瓦底 + 描边、缩略图区退透明；
   文档中心的表格不在 `.arco-card` 里，罩不到"卡内表格退透明"那条，按同一份选择器清单单独摘掉实底。
