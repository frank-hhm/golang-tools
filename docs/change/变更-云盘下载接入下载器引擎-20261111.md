> 状态：**已执行到编译 / 三态构建（Linux 交叉除外）/ 类型检查 / 单测层**
> 完成日期：2026-11-11
> 关联计划：`计划-云盘下载接入下载器引擎-20261111.md`
> 关联里程碑：`计划-功能落地顺序与里程碑-20261030.md`（M9）、`计划-云盘管理工具-20261030.md`（PR4）

## 一、做了什么

把云盘文件「下载」从 `CloudDownload` 自己 `io.Copy` 单连接同步落盘，改成**投递进通用下载器引擎的任务队列**，从而复用引擎已有的队列 / 进度回流 / 暂停 / 取消 / 限速 / 持久化能力，云盘任务与 HTTP 任务在同一张「下载管理」表里统一管理。这是里程碑 M9「云盘打通」验收标准里最后未落地的一半（预览接查看器、进度进任务中心此前已完成）。

为不破坏引擎的通用性，接入采用**依赖倒置**：downloader 侧只定义「外部流源」契约与注册表，云盘侧实现并注册，引擎不反向依赖 `tools/clouddrive`。

## 二、为什么选「外部流源任务」而不是「直链 + 自定义头」

各家 Provider 只暴露 `Open(ctx,id) (io.ReadCloser, size, err)` 一条只读流：Google `alt=media` 要带会刷新的 OAuth 头，百度是限速且会过期的 dlink。直链方案要逐个适配器补 `DownloadURL` 且受各家链接有效期牵制；流源任务对三家通用，只需把「队列 / 进度 / 取消 / 持久化」这层复用出来，不必假装流支持 Range。

跨重启续传：**需要**。云盘任务落进引擎持久化清单，重启后仍列得出、可继续；但流不支持 Range，「续传」对云盘任务 = **整段重下**，UI 与文档如实写明，不谎称断点续传。

## 三、改动清单（按文件）

### 3.1 tools/downloader（通用新增能力）

- **新增 `source.go`（58 行）**
  - `SourceResolver` 接口：`Open(ctx, params map[string]string) (io.ReadCloser, size int64, err error)`，size 未知返回 -1。
  - 包级注册表 `RegisterSource(kind, r)` / `lookupSource(kind)`，`sync.RWMutex` 保护，重复登记同 kind 幂等覆盖。
  - `sortedParamKeys`：params 键排序，供拼稳定 ID 种子（map 遍历无序）。
- **`types.go` Task 加两字段**：`SourceKind string json:"sourceKind,omitempty"`、`SourceParams map[string]string json:"sourceParams,omitempty"`。空 `SourceKind` = 老 HTTP 任务，逐字节行为不变；Store 全量 JSON 序列化让两字段自动往返，重启 `Load()` 把 running/queued 归一成 paused 的逻辑照旧适用。
- **`engine.go` 加 `AddSource(kind, params, opts)`**：与 `Add` 同形但不校验 URL、`Connections` 固定 1（流不可分块）、`kind` 未注册解析器时**拒绝入队**并报错、ID 用 `kind+name+排序后 params` 做种子。
- **`engine.go` `runTask` 加分支**：`if t.SourceKind != "" { m.runStreamTask(t, r, ctx); return }`，否则走原 HTTP `downloadFile`。
- **新增 `stream.go`（125 行）**：`runStreamTask` + `downloadStream` + `streamCopyOnce` + `renamePart`。流程：`lookupSource(kind).Open` → 落 `<savePath>.part`（`O_TRUNC`，从头整段）→ 复用现成 `offsetWriter{tb,ctx,onWrite}` 做限速 / 取消 / 进度回调 → `io.Copy`（size>0 用 `LimitReader`，否则读到 EOF）→ `renamePart`（Windows 先删后 rename 兜底）→ `finish` 统一落终态。重试沿用 `sleepBackoff`，每次 attempt 重新 `Open`（流不能 seek）；**一个字节都没拿到就失败直接透出真实原因**（账号不存在类硬失败不空转退避）。

### 3.2 services/app/clouddrive.go

- 新增 `downloader` import。
- 实现 `cloudSourceResolver`：按 `params["acct"]` 取 Provider 再 `p.Open(ctx, params["file"])`；账号被删 / 不存在时 `Open` 直接返错，任务落 error 态而非静默。
- 新增 `func init() { downloader.RegisterSource("cloud", cloudSourceResolver{}) }`：无 build tag，跨平台，`init` 只往注册表塞一项、早于 `main()` 执行，保证任何 cloud 任务恢复前解析器已就位。
- **重写 `CloudDownload`**：签名不变 `(acctID, fileID, name, dstDir string)`，**返回值语义从「落盘绝对路径」改为「下载器任务 id」**。内部解析 dstDir（空则 `config.CloudCfg().SaveDir` → `appdirs.Data("clouddrive")/downloads`）后 `downloader.Instance().AddSource("cloud", {"acct","file"}, AddOpts{Name, SaveDir, AutoStart:true})`，返回 `t.ID`。删除原 `io.Copy` 直落盘与 `OpTracker` 下载分支（进度改由 `download:progress` 承载）。`CloudUpload` 未动。

### 3.3 frontend/src/views/tools/clouddrive/index.vue

- `download(r)` 改为：调 `CloudDownload` 拿任务 id（快速入队，去掉原整页 `loading` 转圈）→ `Modal.success`「已加入下载队列」，点确定 `openToolWindow("/tools/download", "下载管理", { single: true })` 一键跳转；移除原「已下载到 <路径>」提示。

### 3.4 新增测试

- **`tools/downloader/stream_test.go`（239 行）**：假解析器覆盖 —— 整段落盘逐字节一致、size=-1 读至 EOF、零字节硬失败不重试（断言只 `Open` 一次且透出原错）、未登记 kind 拒绝、进度回调终值正确、中途断开（written>0）退避重试后落完整内容、ctx 超时取消不产出正式文件、`AddSource` 拒绝未登记 kind 与空 kind。

## 四、契约变更与影响面

- `CloudDownload` 返回语义变更（路径 → 任务 id）是**绑定契约变更**。前端唯一调用点在 `clouddrive/index.vue` 的 `download()`，已同步改。绑定 TS 签名 `(acctID,fileID,name,dstDir): Promise<string>` 类型不变（仍是 string），但含义变了。
- 绑定已重生成：`frontend/bindings/Tools/services/app/app.ts`（CloudDownload 新注释）、`frontend/bindings/Tools/tools/downloader/models.ts`（Task 加 `sourceKind`/`sourceParams`）。

## 五、明确不做

- 不给 Provider 接口加 `DownloadURL`、不给 `AddOpts` 加 `Headers`（被否决的直链方案）。
- 不做云盘任务 Range 断点续传（流不支持；重启续传 = 整段重下）。
- 不动 `CloudUpload` / 跨盘转存 `transfer.go` / 预览接查看器。
- 不改下载引擎 HTTP 分块路径（`SourceKind==""` 时逐字节不变）。
