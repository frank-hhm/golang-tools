## 二、Go 侧：`tools/sshgen`（新，跨平台零 cgo，无 build tag）

- `keygen.go`
  - `Generate(ctx, o KeyOptions) (KeyPair, error)`；`KeyOptions{Type(ed25519|rsa|ecdsa), Bits, Comment, Passphrase, Dir, Name}`
  - 算法默认 **ed25519**（快、密钥短、无参数选择坑）；rsa 限定 3072/4096，ecdsa 限 p256/p384/p521
  - 私钥：无口令 `ssh.MarshalPrivateKey(priv, comment)`，有口令 `MarshalPrivateKeyWithPassphrase`；**passphrase 只用于本次派生，不落盘不进任何缓存**
  - 公钥行：`ssh.NewPublicKey` + `MarshalAuthorizedKey` → `<type> <base64> <comment>`
  - 指纹：同时给 `SHA256:…`（OpenSSH 现默认）与 legacy MD5，界面显示前者
  - 落盘：私钥/公钥成对写入 `Dir`（默认 `appdirs.Data("ssh")`），重名避让沿用 `tools/archive` 的 `uniquePath` 思路；写完 `os.Chmod(0600)`（Windows 上语义有限，见「六」）
- `cmds.go`：`CommandsOf(h HostRef) Commands{SSH, SCP, SFTP, ConfigBlock}`
  - 端口非 22 才带 `-p`；有密钥才带 `-i`；**IPv6 地址补方括号**；`keyPath` 含空格要加引号（Windows 路径常态）
  - `ConfigBlock` 用 `Host <别名>` 缩进块，别名做 `~`/空白净化，避免生成不可解析的 config
- `deploy.go`：`Deploy(ctx, h HostRef, pubLine string) (DeployResult, error)`
  - **先严格校验 `pubLine`**：必须是已知前缀 + 合法 base64 + 单行，否则直接拒绝——它最终要写进远端的授权文件，这是提权入口
  - 用密码或已有私钥连上 → SFTP 打开/创建 `~/.ssh/`（0700）与 `~/.ssh/authorized_keys`（0600）→ 读现有内容，**已含同一公钥则报「已存在」不重复追加（幂等）** → 追加写回
  - 全程不走远端 shell，规避命令注入与 `authorized_keys` 权限被 umask 带偏的问题
- `blob.go`：`ExportConn(h HostRef) (string, error)` / `ImportConn(text string) (HostRef, error)`，格式为带版本号的 JSON（`{"kind":"gtools.ssh-conn","v":1,...}`），**只含公钥不含私钥与密码**；导入前校验 kind 与 v
- 单测 `tools/sshgen/*_test.go`：三种算法生成→`ParsePrivateKey` 往返成功且指纹一致；带/不带 passphrase 两条；重名避让；命令片段对 IPv6/空格路径/非 22 端口的输出；config 块可被简单解析器读回；`pubLine` 校验拒绝畸形与注入尝试；部署幂等（连跑两次只有一行）；blob 导出导入往返；均用 `t.TempDir()`

## 六、如实说明（代价与不做）

- **私钥文件格式需实测**：`ssh.MarshalPrivateKey` 输出的是 PKCS#8 PEM，现代 OpenSSH 可读，但个别老服务端/嵌入式 dropbear 可能只认 `BEGIN RSA PRIVATE KEY` 或 OpenSSH 自有格式。实现时先实测本机 `ssh -i` 能否直接用；不通则退到调用本机 `ssh-keygen`（Windows 10+ 自带 OpenSSH 客户端），并在 UI 上说明依赖
- **Windows 下 `0600` 不等价于 POSIX 权限**：NTFS 靠 ACL，`os.Chmod` 只影响部分位。故界面必须提示「私钥目录不要放 OneDrive/同步盘」，不假装我们设了权限
- **部署公钥只保证 Linux/POSIX 远端**：Windows 远端 OpenSSH 的 `authorized_keys` 要求严格 ACL（且管理员组走 `administrators_authorized_keys`），本期不做，遇到 Windows 远端明确报「请用本机方式配置」而不是静默失败
- 幂等靠比对公钥整行（含 base64 与 comment 分离比较：只比类型+base64，comment 不同不算重复），避免同一把钥匙因注释不同被写两遍
- 不做：SSH CA 证书签发、agent 转发与密钥管理、`.ppk` 与私钥格式互转、跳板链上的部署、`known_hosts` 维护（属 SSH 计划 P1）
- 若 SSH 计划的 `Credential` 先落地，本组件回填目标从 `form.keyPath` 改为凭据的 `keyPath`；两者顺序不互为阻塞，只影响这一处接线

## 十一、本机真连验证（2026-11-03）

拿本机 `OpenSSH_for_Windows_9.5p2`（`ssh.exe` + `ssh-keygen.exe`）跑五类互相独立的证据，另加一条负样本：

1. `ssh-keygen -l` 能读私钥指纹 → **PEM 被 OpenSSH 接受**（ed25519 / rsa-3072 / ecdsa-p256 / ecdsa-p384 四种算法 + 带口令一把，全绿）。上面「需人工注意」里「个别老 dropbear 可能不认」的顾虑对 OpenSSH 这条线可以撤销，不必退本机 `ssh-keygen`。
2. `ssh-keygen -y` 导出的公钥与 `sshgen` 写的 `.pub` **逐字节一致** → 公钥行构造正确。
3. `x/crypto/ssh` 客户端连上只认这把公钥的进程内服务器 → Go 侧往返正确。
4. 系统 `ssh.exe` 用该私钥连同一台服务器 → 真实客户端能用（含 Windows ACL 检查）。
5. 负样本：未登记的 ghost 钥匙必须被拒 → 证明 3/4 不是「服务器全放行」造成的假通过。

**验出的硬缺陷（已修）**：`ssh-keygen` 与 `ssh.exe` 一上手就报 `WARNING: UNPROTECTED PRIVATE KEY FILE … This private key will be ignored` 并**完全忽略这把钥匙**。Windows OpenSSH 在加载私钥前查 NTFS ACL，只要有任何他人（目录继承来的 ACE、已注销账号的残留 SID）可读就不用；`os.WriteFile(path, b, 0600)` 在 NTFS 上表达不了这件事。而 `x/crypto` 客户端**不查 ACL**，所以 Go 侧单测全绿也照不出来。

对照实验钉死了它是产品缺陷而不是环境噪声：TEMP 里生成的钥匙拒用；换到真实目录 `bin/data/ssh/`（**另一个不同的 SID**）依旧拒用；而先手动 `icacls` 收紧后 exit=0 全绿 → 障碍只有 ACL 一个。修：新增 `tools/sshgen/acl_windows.go`（`icacls <key> /inheritance:r /grant:r DOMAIN\User:F`）+ `acl_other.go`（no-op），`Generate` 组装完 `KeyPair` 后调用 `tightenKeyACL`，失败只填 `KeyPair.ACLWarning`（`json:"aclWarning"`）不推翻已生成好的密钥。这不是加固，是可用性前提。

仍未验的：「公钥部署到真机 Linux 后关密码登录」。注意一个坑：**不能用 `tools/ftp/server.go` 自连自来验公钥认证**——它只装了 `PasswordCallback`，没有 `PublicKeyCallback`，拿它测公钥会得出假结论（本轮就是这么误过一次，改用验证程序自带的 `ssh.ServerConfig` + 授权表）。
