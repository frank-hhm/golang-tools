## 前置事实（已核对，不是推测）

- `tools/siteclone/siteclone.go`：并发信号量抓多资源，但**每文件 `io.ReadAll` 单连接整块下**，无分块/Range/续传/代理/限速——是引擎要取代的下载内核
- `services/tasks/tasks.go`：只做进度记账（`Observe(event, payload)` + `task:update` + `Snapshot()`），不发起下载、无队列/暂停/续传；引擎进度接进来即可跨页可见（`components/business/task-hub`）
- `tools/browser/manager_windows.go` `buildArgs`：WebView2 空间用 `--proxy-server`/`--no-proxy-server`/`--proxy-bypass-list`，`ProxyMode=system|direct|custom`，建窗时定死、仅 Windows
- `services/config/config.go`：`BrowserConfig`/`BrowserSpace` 已有 `ProxyMode/Proxy/ProxyBypass`；`PathsConfig.Data` 是数据根目录（可建 `appdirs.Data("downloads")`）；工具注册三处：`config.Tools` 默认 + 迁移 extras + `SaveConfig` 防抹
- 无 Go 测速包（speedtest 是前端页）；展速能力由引擎 `Probe*` 提供

## 1. 下载引擎：`tools/downloader/`（新包，跨平台零 cgo，必须带 go test）

### `types.go`
- `type Part struct { Index int; Start, End, Done int64; Speed float64 }`（`End=-1` 未定长）
- `type Task struct`（扁平，供 Wails 生成模型）：`ID,URL,Name,SavePath,Category string; Size,Downloaded int64; Status string`(pending|running|paused|done|error|canceled|queued)`; Connections int; Speed float64; Percent int; Proxy string; Mirrors []string; Source string; Parts []Part; Err,Note string; StartedAt,UpdatedAt,EndedAt,ScheduledAt int64; RetryCount int; AutoStart bool`
- `Options`：`MaxTotalParts`(默认 32)、`MaxRunningTasks`(默认 3)、`DefaultConnections`(默认 4)、`GlobalSpeedLimitBps`(0=不限)、`MinSegmentedSize`(默认 4MB)

### `engine.go`（调度与生命周期）
- 单例 `Manager`：`Add/Start/Pause/Stop/Resume/Retry/Delete/SetConnections/SetSpeedLimit/SetProxy/SelectSource/List/Snapshot`
- 调度循环：running 数受 `MaxRunningTasks` 限，超了置 `queued`；全局 `sem chan struct{}` 容量 `MaxTotalParts` 控总块并发；`ScheduledAt>0` 到点自动 Start（`time.Timer`/ticker，跨平台）
- 每任务一个 goroutine 编排 N 个 part worker（`sync.WaitGroup` + `context` 取消=暂停/停止）

### `fetch.go`（分块 + 续传 + 重试）
- `probe(u)`：`HEAD`（或 `GET`+`Range: bytes=0-0`）取 `Content-Length` 与 `Accept-Ranges`
- 可分块（定长 且 ranges 且 `size>MinSegmentedSize`）：按 `Connections` 切 N 段，各段 `GET Range: bytes=s-e`，`file.WriteAt` 落偏移；目标文件先 `os.Truncate(size)` 稀疏预分配
- 不可分块/服务端返回 200 而非 206：退化单连接流式写 `<name>.part` → 完成 rename
- 续传：每任务旁写 `<name>.gtdl.json`（记各 part `Done` 偏移）；重启/Resume 读回，只对未完成区间重发 Range；完成删 meta
- 重试：part 级指数退避（上限 `maxRetry`），4xx（除 408/429）判致命；`RetryCount` 记账
- 限速：包内**自实现令牌桶**（不引 `x/time/rate`），全局 + 每任务两层，写循环 `Wait(n)`
- HTTP client：`Transport` 支持 `Proxy`（http/https，`http.ProxyURL`；socks5 视 `x/net/proxy` 是否在依赖树决定，不硬引），带 UA/Referer/超时/跳数上限（沿用 siteclone 护栏常量风格）

### `probe.go`（手动选源 + 展速，不做自动切）
- `ProbeSources(mirrors []string) []SourceStat`：各镜像 HEAD + 限时 GET 前若干 KB，估 `LatencyMs/AvgSpeed/OK`
- `ProbeProxies(list []string, testURL string) []ProxyStat`：经各代理访问 testURL，测延迟/吞吐/可用性
- 前端展示，用户手动 `SelectSource/SelectProxy`；引擎不自动切换（PR4 再接策略）

### `store.go`（持久化）
- 任务清单 JSON 落 `appdirs.Data("downloads")/tasks.json`；启动加载 `running→paused`（不自动续跑，避免重启风暴），`ScheduledAt` 未到点保留
- 分类规则：按扩展名映射 `压缩/文档/音乐/程序/视频/图片/其他`（写死一张表，仿 FlashGet 分类）

## 8. 校验口径与顺序

1. `gofmt -w tools/downloader services/app/download.go services/config/config.go`（`main.go`/`main_server.go` 若 CRLF 禁止整文件 gofmt，只加 init 那行）
2. `go vet ./...`
3. `go test ./tools/downloader/... -count=1` — 覆盖：
   - `httptest` 起支持 Range 的服务器：多分块下载**逐字节重组一致**、`Connections` 生效、206 vs 200 退化单流、`Accept-Ranges:none` 走 `.part` 路径
   - 续传：中途 Pause 再 Resume，`<name>.gtdl.json` 偏移正确、不重复下载已完成段、最终 size 对
   - 限速：令牌桶下吞吐不超上限（放宽时间窗断言）
   - 重试：注入一次 500 后成功；致命 404 不重试
   - `ProbeSources/ProbeProxies`（假服务器）返回 OK/Latency 合理
   - store：running→paused 归一、分类扩展名映射
4. `go build .`（Windows 桌面）
5. `$env:GOOS="linux";$env:GOARCH="amd64";$env:CGO_ENABLED="0"; go build -tags server -o bin/_linux_check .`
6. `wails3 generate bindings -clean=true -ts -i`（版本同 go.mod）→ 提交 `frontend/bindings`
7. 前端：`npx vue-tsc --noEmit` → `npm run build`；`dist` 不入库，部署前重建
