## 一、需求与当前真实差距

里程碑 M9「云盘打通」验收标准：**云盘文件点开走查看器、下载进下载器队列**。核对代码后：

- ✅ 预览接查看器：`clouddrive/index.vue` 已用 `openToolWindow('/tools/viewer?src=cloud…')`。
- ✅ 下载/上传进度已进任务中心：`cloud:progress` + `OpTracker`（PR3/PR4 已交付）。
- ❌ **下载没进「下载管理器」那张任务表**：`services/app/clouddrive.go` 的 `CloudDownload` 仍是自己 `io.Copy` 单连接同步落盘，拿不到引擎的队列 / 暂停 / 续传 / 限速 / 统一列表。

本计划只做这最后半句。

## 二、已确认的两个语义（用户选择）

| 维度 | 取定 | 理由 |
|---|---|---|
| 接入方式 | **外部流源任务**（不是直链+自定义头） | Provider 只给 `Open()` 流：Google `alt=media` 要带会刷新的 OAuth 头、百度是限速会过期的 dlink。直链方案要逐个适配器造 `DownloadURL` 且受各家有效期牵制；流源任务对三家通用，且把"队列/进度/取消/持久化"这层复用出来即可，不假装 Range 可用 |
| 跨重启续传 | **需要** | 云盘任务落进引擎持久化清单，重启后仍列得出来、可继续；但流不支持 Range，"续传"对云盘任务=**整段重下**（仍在队列里可见可控），文档与 UI 如实写明，不谎称断点续传 |

## 三、核心约束：downloader 不得反向依赖 clouddrive

引擎是通用下载器，云盘是它的一个消费者。接法用**依赖倒置**：引擎定义"源解析器"契约 + 注册表，云盘侧实现并注册。引擎只认一个不透明 `params map[string]string`，怎么把它变成一条 `io.Reader` 完全交给注册的解析器。

## 四、改动设计

### 4.1 tools/downloader（通用，新增能力）

- **新增 `source.go`**：
  - `type SourceResolver interface { Open(ctx context.Context, params map[string]string) (io.ReadCloser, int64, error) }`（size 未知返回 -1）。
  - 包级注册表 `RegisterSource(kind string, r SourceResolver)` + `lookupSource(kind)`，`sync.RWMutex` 保护。注册是幂等覆盖，供消费者在 init/启动时挂。
- **`Task` 加两字段**（`types.go`）：`SourceKind string json:"sourceKind"`、`SourceParams map[string]string json:"sourceParams"`。空 `SourceKind` = 老 HTTP 任务，行为逐字节不变。Store 全量 JSON 序列化 → 两字段自动往返，重启 `Load()` 把 running/queued 归一成 paused 的逻辑照旧适用。
- **新增 `AddSource(kind string, params map[string]string, opts AddOpts) (*Task, error)`**（`engine.go`）：与 `Add` 同形但不校验 URL、`ID` 用 `uniqueID(kind+"|"+name+"|"+join(params))` 生成、`Source` 字段留空。`kind` 未注册解析器时**拒绝入队**并返回明确错误（避免建出一个跑不动的任务）。
- **`runTask` 分支**：`if t.SourceKind != "" { m.runStreamTask(t, r, ctx); return }`，否则走现有 HTTP `downloadFile`。
- **新增 `stream.go`**：`runStreamTask` + `downloadStream`。流程：`lookupSource(kind).Open(ctx, params)` 拿 reader+size → 落 `<savePath>.part`（`start=0`、`O_TRUNC`，流无 Range 不续偏移）→ 复用现成 `offsetWriter{tb,ctx,onWrite}` 做限速/取消/进度回调 → `io.Copy` → rename `.part`→`savePath`（Windows 先删后 rename 兜底，同 `downloadSingle`）→ `emitProgressSingle`。取消/错误由 `finish` 统一收尾（`r.kind` 已区分 pause/stop）。重试沿用 `streamSingle` 那套 `sleepBackoff`，但每次 attempt 重新 `Open`（流不能 seek）。

### 4.2 services/app/clouddrive.go

- **实现并注册 cloud 源解析器**：
  ```go
  type cloudSourceResolver struct{}
  func (cloudSourceResolver) Open(ctx context.Context, params map[string]string) (io.ReadCloser, int64, error) {
      p, err := cloudProvider(params["acct"]); if err != nil { return nil, 0, err }
      return p.Open(ctx, params["file"])
  }
  func init() { downloader.RegisterSource("cloud", cloudSourceResolver{}) }
  ```
  `init` 只往注册表塞一项、无副作用顺序依赖，跨平台无 build tag。
- **`CloudDownload` 改为投递进引擎**：签名不变 `(acctID, fileID, name, dstDir string)`，但**返回值语义从"落盘绝对路径"改为"下载器任务 id"**。内部：解析 dstDir（空则 `config.CloudCfg().SaveDir`→`appdirs.Data("clouddrive")/downloads`，同现在）→ `downloader.Instance().AddSource("cloud", {"acct","file"}, AddOpts{Name, SaveDir, AutoStart:true})` → 返回 `t.ID`。删除原 `io.Copy` 直落盘与 `OpTracker` 下载分支（进度改由 `download:progress` 承载）。`CloudUpload` 不动。

### 4.3 前端 clouddrive/index.vue

- `download(r)`：调 `CloudDownload` 拿到任务 id → `Message.success("已加入下载队列，可在「下载管理」查看")`，附一键 `openToolWindow("/tools/download", …)`。移除原"已下载到 <路径>"提示（不再有同步路径）。

### 4.4 接线与任务中心

- `download:progress` 事件、`services/tasks` 的 `tool=="download"` 台账主键（用引擎 id）已在下载器 PR 里就绪，云盘任务天然复用，**无需新增事件、无需改 tasks.go**。
- 下载管理页 `CATEGORIES` 已按扩展名归类，云盘任务按文件扩展名自动归桶；`AddOpts.Category` 留空即可。

## 五、明确不做

- 不给 Provider 接口加 `DownloadURL`、不给引擎 `AddOpts` 加 `Headers`（那是被否决的直链方案）。
- 不做云盘任务的 Range 断点续传（流不支持；重启续传=整段重下）。
- 不动 `CloudUpload`/跨盘转存 `transfer.go`/预览接查看器（均已完成）。
- 不改下载引擎的 HTTP 分块路径（`SourceKind==""` 时逐字节不变）。

## 七、风险

- **返回值语义变更**：`CloudDownload` 从"路径"变"任务 id"，是绑定契约变更，须同步改前端调用点（唯一调用在 clouddrive/index.vue），否则前端 toast 显示错。
- **账号被删后重启**：持久化的云盘任务 resume 时 `cloudProvider(acct)` 失败 → 任务进 error 态并如实报"账号不存在"，不崩。
- **大文件整段缓冲**：解析器 `Open` 返回的是 provider 流，`downloadStream` 边下边写 `.part`，不整段进内存（与转存的内存缓冲不同），内存安全。
