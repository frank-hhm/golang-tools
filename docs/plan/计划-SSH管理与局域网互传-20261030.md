## 零、现状盘点（已核对，不是推测）

`tools/term`（ssh.go 8KB + term.go 7KB + docker.go + secret_windows/other.go）已有：

- `Host{id,name,system,address,port,user,auth(password|key),keyPath,note,updatedAt}`，存 `data/term/hosts.json`（`hostRecord` + `storePath/readRecords/writeRecords`）
- 密码经 `secret.Protect/Unprotect`（Windows DPAPI，其他平台 fileCred，见 `services/sysx/cred_windows.go`、`cred_file.go`）
- `OpenSSH(hostID,cols,rows)` → PTY；`Write(sessionID, dataB64)`、`Resize`、`Close`、`CloseAll`；`SetEmitter` + `emit` 推 `term:data`/`term:exit`；`Test(h)` 返回连接延迟
- 前端：`@xterm/xterm@5.5` + `@xterm/addon-fit` 已装，`components/business/term-console/index.vue`（10KB）+ `HostFormModal.vue`（7KB）+ `TermHost`/`TermTab` 类型

缺口（本计划要补的）：主机无分组/标签/搜索、凭据与主机绑死（一台机器一份密码）、**无 known_hosts**（`ssh.go` 里是 `ssh.InsecureIgnoreHostKey()`，注释自陈「个人自用工具：不维护 known_hosts，首次连接不做指纹确认」）、不读 `~/.ssh/config`、与 `tools/ftp` 的 SFTP 连接簿**两套完全不通**。

## 一、决策摘要（已确认）

| 维度 | 取定的做法 | 明确不做 |
|---|---|---|
| SSH 范围 | **补齐缺口与凭据体系**：分组/标签/搜索、凭据与主机分离、known_hosts 改 TOFU、导入 `~/.ssh/config`、与 FTP SFTP 互通 | 端口转发与隧道管理（-L/-R/-D）、跳板机多跳、批量执行、会话录制回放 |
| 互传形态 | 本机起 HTTP 服务，局域网设备浏览器打开 `http://<ip>:<port>` 即可上传到收件箱、下载被授权的条目 | 公网外链、内网穿透、账号体系 |
| 安全边界 | **上传免密 + 下载白名单**：任何局域网设备可传到收件箱；能下载什么必须由用户显式授权 | 共享根整层开放（等于局域网匿名 FTP）、每笔操作回主界面确认 |
| 分享内核 | **合并为一个 `tools/lanshare`**：一个监听、一套路由，两种模式（常驻互传门户 / 临时分享链接）；文档中心 P3 改为接入 | 两套局域网 HTTP 服务各写一遍（抢端口、重复上传与限流逻辑） |
| 服务开关 | 默认关闭，手动启停 + 可设到点自动停；关闭时不 listen、不注册路由 | 开机自启、常驻监听 |
| 凭据存储 | 继续用 `sysx.Cred`（DPAPI / fileCred），口令永不明文落盘 | 自建加密方案、把私钥内容拷进我们的库 |

## 三、P1 known_hosts（TOFU）与配置导入

- `tools/term/knownhosts.go`（新）：OpenSSH 兼容格式 `data/term/known_hosts`；`HostKeyCallback` 换成自实现——首次连接记录指纹并提示确认（TOFU），已记录但不匹配则**硬阻断**并给出「指纹变化，可能被中间人；确认后再替换」的显式操作
- 三档策略进设置：`strict`（不匹配即断）/ `tofu`（默认，首次静默记录）/ `off`（维持现状 `InsecureIgnoreHostKey`，只给老用户兼容）
- 支持导入系统 `~/.ssh/known_hosts`（去重合并，不覆盖本机已记录项）
- `tools/term/sshconfig.go`（新）：解析 `~/.ssh/config` 的 `Host/HostName/User/Port/IdentityFile/ProxyJump/ForwardAgent`，**只导入为可编辑的主机草稿列表**（用户勾选后才落库），不接管运行时语义——避免与 x/crypto/ssh 的实际能力产生假承诺（ProxyJump 本期不支持，导入时明确标注为未生效字段）
- 与 FTP 互通：`tools/ftp` 的 `Connection(type=sftp)` 与 `term.Host` 共用同一份 `Credential`，两侧各加「在终端中打开 / 在 SFTP 中打开」互跳；不合并两套连接簿的存储结构（改动面太大），只在凭据层归一
- 端到端测试资产：`tools/ftp/server.go` 本身就是一个 SFTP/SSH 服务器，**用它自连自**跑 known_hosts 首次记录、指纹不匹配阻断、密码与公钥两条认证路径（不需要外部 SSH 环境）

## 四、P2 lanshare 内核（互传门户 + 分享链接）

`tools/lanshare`（新，跨平台零 cgo，**无 build tag**，Linux 面板构建同样存在）：

- `server.go`：监听选择（默认全部网卡，可指定单 IP / 仅本机回环）、端口占用则 +1 重试（listen 与限流写法参照 `tools/ftp/server.go`）、优雅停止、局域网 IPv4 枚举供界面展示与二维码
- `portal.go`（互传门户，免密）：
  - 首页 = 拖拽上传区 + 已授权下载列表；默认页与收件箱目录可配（用户要的「可以设置默认页或对应目录」）
  - 上传：`multipart` **流式**落 `data/lanshare/inbox/`（不整读进内存），大小上限、扩展名/MIME 白名单、文件名净化 + `safeJoin` 防目录穿越（复用 `services/sysx` 的 `safeJoin` 思路，archive 解压已验证过同一类问题）、重名避让
  - 下载：只允许 `grants.json` 里显式授权的条目（路径 + 是否含子目录 + 有效期），未授权一律 404 而非 403（不泄露路径是否存在）

- `link.go`（临时分享链接）：token（`crypto/rand`）+ 有效期 + 下载次数上限 + 单文件/目录打包（目录走已完成的 `tools/archive` 引擎流式打包），**这是文档中心 P3 的落点**
- `access.go`：访问日志（时间/来源 IP/动作/条目/字节），滚动写入，供事后核对谁传了什么
- 可选 PIN：默认关闭（用户明确要免密），开启时仅挡无意访问，文档里如实写明它不是访问控制
- 自动停止：默认 N 小时后自停并在界面提示，符合「不启用就不挂载」
- 绑定：`LanShareStatus/Start/Stop/SetGrants/RevokeGrant/CreateLink/RevokeLink/ListLinks/SetInbox/SetAutoStop`；传输进度接 `services/tasks`（`events` 加 `"lanshare:progress": {"op", "name"}`，`toolNames` 加 `"lanshare": "局域网互传"`）
- 前端：`views/tools/lanshare/index.vue`（服务状态、IP+端口、二维码复用现有 `qrcode` 能力、授权管理、收件箱列表）；设置页新增分区

**与计划的偏差（如实）**：
1. 分组做成了左栏筛选下拉而非整棵分组树（列宽 span 7 放不下树 + 列表），标签同理；功能等价（按分组/标签过滤），视觉降级。
2. **FTP⇄term 凭据层归一与「在终端中打开 / 在 SFTP 中打开」互跳**——P0/P1 轮暂缓，**已于 2026-11-04 P2 收尾交付**（见末尾第十节）：`tools/ftp` 与 `tools/term` 仍是两套存储（`connections.json` vs `credentials.json`），归一只在 `services/app` 绑定层做桥接（`resolveFtpConn` 按 credID 叠加），两 tools 包保持互不依赖。
3. known_hosts 端到端**未采用 `tools/ftp/server.go` 自连自**：其 `hostKeySigner` 未导出、监听端口固定，跨包耦合脆弱；改在 `term` 包内自建 `ssh.ServerConfig` 测试服务器跑真实握手，覆盖密码认证路径 + TOFU 首记。公钥认证路径由 `hostKeyCallback` 单测层覆盖（不经 live server）。指纹不匹配阻断亦在 callback 单测覆盖（复用同一 host:port 换密钥，避免临时端口变化）。
4. fileCred 回退：无法在 Windows 上强制「DPAPI 不可用」，跨平台解密失败路径靠 `secret` 包既有约定（`plain:` 前缀 + 非 Windows 遇 DPAPI 密文报错），term 单测只保证本平台 protect/unprotect 往返 + 迁移/解析走通。
5. 设置页未新增 SSH 独立分区：known_hosts 策略与导入放在终端页的「主机密钥」弹窗内，控制粒度到全局（影响所有 SSH 连接），够用。

## 五、如实说明（代价与不做）

- **不做端口转发与隧道**（-L/-R/-D）、不做跳板机多跳、不做批量执行与录制回放——这是选定范围 A 的边界，不是遗漏；若后续要转发，`Credential` 与 `knownhosts` 两层已可直接复用
- 免密上传意味着**局域网内任何设备都能往收件箱塞文件**：靠大小上限、类型白名单、收件箱配额与自动停止兜底，不靠认证。收件箱目录必须是不能执行的位置，且界面提示「不要从收件箱直接双击运行任何文件」
- `off` 策略保留 `InsecureIgnoreHostKey` 是给老用户的兼容档，默认档必须是 `tofu`
- 面板构建下 lanshare 是**独立端口、不经 panel 登录墙**（否则免密无意义），界面上要明确标出「此端口对局域网开放」，并提供只监听指定网卡的选项
- ProxyJump 导入后标注为未生效字段，不做静默忽略——避免用户以为跳板已生效
- 与 FTP 连接簿只在凭据层归一，两套存储结构不合并
