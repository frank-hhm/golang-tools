## 二、必须先说清的一件事：图标角标做不了

TortoiseGit 最显眼的是文件旁的状态角标，但它是 **in-proc COM 服务器**（`ShellIconOverlayIdentifiers` 注册一个 DLL），代价与风险：

1. 要产出真正的 Windows DLL 导出 `IClassFactory`，Go 侧需 `cgo` + `-buildmode=c-shared` 或手写导出表 —— **直接违反 AGENTS 的 `CGO_ENABLED=0` 跨平台零 cgo 约束**
2. 系统全局只认前 15 个 overlay identifier，按注册表键名字典序竞争，与 OneDrive/TortoiseSVN/NAS 客户端抢位是长期投诉源
3. Windows 11 已改用稀疏植被（sparse）机制，传统 overlay 在新系统上表现不稳，TortoiseGit 自身在 11 上就常出问题
4. DLL 需 regsvr32 级注册与位数匹配，卸载残留风险高

**替代方案**（本计划采用）：状态可见性放在**工具页的多仓库面板**（列出所有已登记仓库 + 脏/领先/落后/冲突计数 + 一键打开）与**右键菜单文字**（`Git (Tools) — 3 个改动`）上。不写 COM，不碰系统级扩展点。

## 三、架构：三层

1. `tools/gitcmd`（新，纯 Go，跨平台零 cgo）—— git.exe 发现、命令 runner（捕获 stdout/stderr、超时、`-z` 与 `--porcelain` 解析）、领域模型。**不含 UI 语义**
2. `services/app/git.go`（新，**无 build tag**）—— 绑定方法 + `git:progress` 事件 + CLI 分流入口
3. `frontend/src/views/tools/git/`（新工具页）—— 仓库工作台；右键经转交层唤起它

## 四、P0 引擎层与单实例转交抽取

- 抽取：把 archive 的转交实现提为 `services/singleinstance`（端点文件 + crypto/rand 令牌 + 回环 TCP），archive 与 git 各用自己的服务名与端点文件，**行为不变**；抽取后必须先跑一次压缩功能的回归（`ArchiveCLICommand` 分流、转交、Preflight）
- `tools/gitcmd/discover.go`：`LookPath("git")` + `git --version` 校验最低版本（porcelain v2 需 ≥2.11，`--auto-stash` 等新旗标另设门槛），未装返回明确错误码供前端引导安装（沿用 Docker Desktop 那套「检测到缺失即中止并提示」的处理）
- `tools/gitcmd/run.go`：`Run(ctx, repoDir string, args ...string) (Out, error)` —— 统一 `-c color.ui=false`、`--no-optional-locks`、`-z` 按需、`LC_ALL=C` 固定解析语言、`SysProcAttr{HideWindow}`、超时与 ctx 取消杀进程树、stderr 里提取 `fatal:`/`error:` 首行做人话错误
- `tools/gitcmd/repo.go`：`Discover(path)`（向上找 `.git`，支持 worktree 与 `git rev-parse --show-toplevel --git-dir --is-bare-repository`）、仓库登记表 `data/git/repos.json`
- `tools/gitcmd/status.go`：`Status --porcelain=v2 --branch -z` → 分 staged/unstaged/untracked/conflicted + 领先落后计数
- `tools/gitcmd/log.go`：`rev-list --parents --pretty` + lane 分配算法（自研，约 120 行：按父提交延续分支占位，输出每 commit 的 `(lane, parents[])`），前端只画不算
- `tools/gitcmd/diff.go`：`diff --numstat`、`show`、`diff -- <path>` 取 unified patch
- 单测：`tools/gitcmd/*_test.go` 用 `git init` 建临时仓库真实跑（**检测不到 git 则 `t.Skip`**，不编造假数据），覆盖 status 各态、lane 布局对线性/合并/分叉图的正确性、路径含中文与空格、`-z` 解析、非仓库目录、游离 HEAD

## 八、P4 右键集成与开关

- 复用压缩那套 HKCU verb 注册，命名空间独立：`Software\Classes\Directory\shell\ToolsGit`（及 `*`、`Background`），菜单项 `Git (Tools) — 仓库状态 / 提交 / 推送 / 拉取 / 分支`
- 上下文判断在**程序内**做：verb 触发后 `git rev-parse --is-inside-work-tree`，不在仓库就 toast 说明，不改菜单可见性（原生 shell 条件注册要写 COM，与「二」同因不做）
- CLI 分流：`GitCLICommand(args) (op, repo string, ok bool)` 只认精确标记，与 archive 标记互不冲突；命中后经 `services/singleinstance` 转交，无实例则本进程直接开工具页定位到该仓库
- **开关**：`git.shellEnabled` 关闭时不注册 verb、不写 SendTo、不加载仓库表、不启任何后台逻辑；打开才 `mountGitHost()` + `syncGitShell()`，与「不启用就不挂载」范式一致
- 卸载彻底：删除自己写的 HKCU 键，不碰 archive 的键，不残留 SendTo 快捷方式

## 九、如实说明（代价与不做）

- **不做图标角标**，原因见「二」，这是硬约束（CGO_ENABLED=0）下的正确取舍，不是偷懒
- **必须本机装 git**：未装时功能整体不可用，前端给出明确提示与安装入口；我们不分发也不内嵌 git 运行时
- 极老版本 git（<2.18）部分旗标缺失，按能力探测降级，不保证全功能
- 超大仓库（百万文件级）`git status` 本身就慢，手动刷新策略下不会自动卡住，但首次进入大仓库仍需等待；不做索引加速
- 不做：submodule、LFS、hooks 编辑、reflog、bisect、交互式 rebase 图形、GitHub/GitLab PR 集成、blame 注释重写
- 凭据完全交给系统 credential helper：好处是不在我们磁盘上留任何令牌，代价是首次推送可能弹出 git 自己的认证窗（这是 git 的行为，不拦截）

## 十、校验口径与顺序

1. `gofmt -l tools/gitcmd services/app/git.go`（`main.go`/`app.go`/`tasks.go` 是 CRLF，**禁止整文件 `gofmt -w`**）
2. `go vet ./tools/gitcmd ./services/app ./services/singleinstance`
3. `go test ./tools/gitcmd/... ./services/singleinstance/... -count=1`（临时仓库真实 git；无 git 环境 `t.Skip`）
4. `go build -o bin/_gt.exe .`（`go build .` 因 tools/ 大小写冲突不可用）
5. Linux 面板双构建：`$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"; go build -tags server -o bin/_linux_check .`
6. 前端：`npx vue-tsc --noEmit` → `npm run build`（vite 需 Node ≥20，用 `D:\nvm\v22` 直跑）；`@codemirror/merge` 与 HistoryPane 必须 dynamic import
7. 真机回归：转交层抽取后**压缩功能必须先回归一遍**（右键压缩/解压、CLI 分流、无实例直跑），再验 Git 右键；Windows 桌面外，Linux 面板下 Git 只读浏览服务器仓库为预期语义
