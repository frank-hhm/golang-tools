> 状态：**已执行完成**（2026-10-30，编译 / 单测 / 前端构建 / headless 命令行实测均通过；资源管理器点击链路待真机验一次）

## 决策摘要（已确认）

| 维度 | 取定的做法 | 明确不做 |
|---|---|---|
| 格式 | `zip`(Deflate) + `tar.gz`，双向（压缩 + 解压） | 加密 zip、分卷、7z、rar、外部 7-Zip 调用 |
| 挂载 | HKCU 静态注册表 verb + SendTo 快捷方式 | `IExplorerCommand` COM + MSIX（进不了 Win11 顶层菜单的收益不值当） |
| 干活进程 | 主程序在跑 → 命名管道转交；没跑 → 本次调用无界面压完退出 | 引入 Wails `SingleInstance`（会牵连 `wails3 dev` 与安装实例互斥，改动面比收益大） |
| 界面 | 主窗口工具页 + 压缩前可选项小窗 | — |
| 开关 | 设置页总开关，关时不写注册表、不起管道、面板窗不建 | 默认开启（默认关闭，用户主动挂） |

## 前置事实（已核对，不是推测）

- `golang.org/x/sys/windows/registry` 仓库里已在用（npm / docker / sniffer），不引新依赖
- ~~Go 1.25：`net.Listen("pipe", ...)` 原生可用，命名管道不需要 syscall~~ **执行时被实测推翻**：本机 Go 的 `net` 包没有 `pipe` 网络注册，探针直接报 `listen pipe: unknown network pipe`。转交层改为**回环 TCP（`127.0.0.1:0`）+ 端点发现文件 + `crypto/rand` 令牌**，原因写在 `services/archivehost` 文件头；下方第 3 节的管道名/`Listen("pipe")` 描述按此实现
- `services/app/app_platform_windows.go:64` 的 `ShowSystemNotification` 实现体只用 `effectiveAppName()` + exec PowerShell，**不碰 `a.app`** → 无界面分支能直接调
- `services/sysx/extract.go` 已有 zip/tar.gz 解包 + zip-slip 防护（`safeJoin`），压缩就是它的镜像
- 生产构建 `-H windowsgui`：右键拉起不闪控制台
- 写不了（标准库限制）：加密 zip、7z、rar、分卷

## 1. 压缩原语：`services/sysx/compress.go`（新）

`extract.go` 的镜像，同包同文档块风格，只放"系统能力原语"，不含业务编排。

- `compressArchive(src []string, dst, format string, level int) error`
  - `zip`：`archive/zip` + `flate`；`targz`：`archive/tar` + `compress/gzip`
  - 级别 3 档：`fast`=`gzip.BestSpeed(1)`、`normal`=6、`max`=`gzip.BestCompression(9)`；zip 侧用 `w.Level(...)` 同值映射
  - **一律先写 `dst + ".part"`，全部成功后 `os.Rename` 落名**：中途失败不留半个压缩包；失败路径上删掉 `.part`
  - 目录条目显式写入（zip 以 `/` 结尾的 header，tar 的 `TypeDir`），保证空目录不丢
  - 符号链接：跳过并在返回值里记账（Windows 上跟随链接有环风险，且 zip/tar 的软链语义两端不一致）
  - 读不动的文件（被占用、无权限）：**跳过 + 记账，不中断整包**；一条都没写成功才报错
  - 输出文件本身必须排除在输入集合外（压缩整目录时它会自包含）
- 保留位：非 Windows 上写 unix mode（与 `extract.go` 的 `mode` 处理对称），Windows 上无意义不写

## 2. 业务编排 + 系统挂载：`tools/archive/`（新包）

### `archive.go`（平台无关）

- `Job` / `Progress` / `Result` 三个扁平结构（要生成前端模型，不嵌套）
- `Compress(paths []string, opt Options) (Result, error)`：
  - 预扫描累计总字节 → 按已写字节发进度（每 ~200ms 或每 32 个条目节流一次）
  - 输出命名规则（写死，避免实现时再议）：
    - 单条目 → `<去扩展的原名>.zip` / `.tar.gz`，落在原条目所在目录
    - 多条目 → 取公共父目录的 basename；父目录是卷根、或 basename 属于已知文件夹名（Desktop/Downloads 等）时退化为 `压缩包`
    - 目标已存在 → `name (1).zip`、`name (2).zip` 递增
  - `ctx` 可取消（任务中心要能停）
- `Extract(archive, dstDir string) (Result, error)`：直接委托 `sysx` 现成的 `extractArchive`（zip-slip 防护已在里面），默认解到 `dirname\` 同级文件夹，同名已存在则加序号
- `func Enabled() bool`：读配置总开关，与 `tools/launcher` 同一套闸门写法

### `shell_windows.go`（`//go:build windows`）

写 **HKCU，不需要管理员**。键布局：

```
HKCU\Software\Classes\*\shell\GoToolsArchive\command
    = "{exe}" --archive "%V"
HKCU\Software\Classes\Directory\shell\GoToolsArchive\command
    = "{exe}" --archive "%V"
HKCU\Software\Classes\SystemFileAssociations\.zip\shell\GoToolsExtract\command
    = "{exe}" --extract "%1"
（.tgz / .tar.gz 关联同样各写一条；.tar 不写，extractArchive 不支持）
```

- **必须用 `%V` 而不是 `%1`**：`%1` 多选只拿第一个
- verb 键上写 `MUIVerb` / `MultiSelectedModelString`（后者决定是否在多选中出现），以及 `Icon` = `"{exe},0"`
- SendTo：`%APPDATA%\Microsoft\Windows\SendTo\压缩为 ZIP.lnk`，target = exe，arguments = `--archive-panel`。`.lnk` 用一行 PowerShell `WScript.Shell CreateShortcut` 生成（沿用 toast 的 exec 写法，`HideWindow: true`），不引第三方 COM 包
- `ShellStatus()`：逐键读回，返回"已挂载 / 未挂载 / exe 路径与当前不一致"——**exe 挪位置后能自修复**（启动时或打开设置页时检测到不一致就重写）
- `ShellInstall()` / `ShellUninstall()`：卸载删干净自己写过的键与 `.lnk`，绝不碰别人的键

### `shell_other.go`（`//go:build !windows`）

全部返回 `sysx.ErrUnsupported`，前端按 `Capabilities` 隐藏挂载区（与 `ShowSystemNotification` 的非 Windows 处理一致）。

## 3. 进程间转交：`services/archivehost/`（新包）

- 管道名固定 `\\.\pipe\go-tools-archive`
- `Listen(onJob func(Job)) error`：主程序启动时（**仅当总开关开着**）起一个 goroutine，`net.Listen("pipe", ...)`
  - 已有主程序占着管道 → `Listen` 失败**只记日志，不报错退出**（两个 GUI 实例并存的既有行为不变）
- `TrySend(job Job) bool`：拨号带 400ms 超时；连上就发 JSON、读到 `ack` 即返回 true；连不上返回 false（= 主程序没跑）
- 负载协议：一条 JSON `{op, paths, format, level, outDir}` + 换行分隔，收到即 `ack`
- 实现差异（因上面的管道前提不成立）：监听地址是 `127.0.0.1:0` 动态端口，真实地址写进端点发现文件（与令牌同存，`crypto/rand` 32 字节），`TrySend` 先读端点文件再拨号；只监听回环，令牌不匹配直接断连

## 4. 入口分流：`main.go`（`//go:build windows && !server`）

插在 `config.LoadAppConfig()` + `applog.Init()` 之后、`application.New()` 之前：

```
--archive / --extract  → TrySend 成功？ 是：os.Exit(0)
                                          否：headless 压完（不建任何窗口、不注册热键、不起托盘、不建索引）
                                              → 成功/失败各弹一次 ShowSystemNotification → os.Exit(0)
--archive-panel        → 记进 startupArgs，正常起 GUI，主窗口就绪后开选项小窗
其余                   → 现有启动路径完全不变
```

- 只有 `--archive` 这类显式标记才走分流，普通双击启动零影响 → **不开 `SingleInstance`，`wails3 dev` 与安装实例照旧能并存**
- `main_server.go` / `main_other.go`：**不接 CLI 分支**（服务端/桌面占位入口没有右键语义），只共享第 5 步的绑定方法
- `main.go` 是 CRLF，禁止整文件 `gofmt -w`

## 7. 必须真机验证的不确定项（写代码前不假装已知）

1. `%V` 在 `command` 串里的展开形态：多个选中项是否真的以**空格分隔的带引号全路径**并进一条命令行（决定 `os.Args` 要不要二次切分）
2. SendTo `.lnk` 多选时的传参形态（每个路径一个 arg，还是挤成一个）
3. Win11 25H2 静态 verb 是否确实只出现在「显示更多选项」二级菜单（预期是，作为已知代价告知用户）
4. `-H windowsgui` 无控制台进程作为 verb 目标被资源管理器拉起时，工作目录与参数传递是否正常
5. 大目录（10 万+ 文件）预扫描耗时与进度粒度；`archive/zip` 在单文件 >4GB 时的 zip64 行为

1. `gofmt -w` 新写的 Go 文件（LF）
