## 前置事实（已核对，不是推测）

- `sysx.Open()` 的 `Opener` 有 `Dir/File/Launch`：Windows 走 `ShellExecuteW`/explorer，Linux 走 `xdg-open`（headless 无桌面时返回 `ErrUnsupported`，见 `services/sysx/open_*.go`）
- `services/app/disk.go` + `tools/disk/disk.go`：`DiskList` 可整卷浏览（`filepath.Abs`，无 root 约束），但**没有读文件内容 / 写文件内容 / 预览**——本工具页补齐这块
- `tools/ftp/client_sftp.go` 已有 `FtpPreview`（`Kind: text|image|binary|tooLarge`，`previewTextMax=1<<20`、`previewImageMax=8<<20`，用 `bytes.IndexByte(buf,0)`+`utf8.Valid` 判二进制）；其 `Preview{}` 结构与判定写法是本页 `ReadText/ReadBinary` 的直接模板
- `components/business/body-viewer` 已实现 image/video/pdf 的 `preview`（dataURL/`iframe`）与 HEX 视图，可复用其底衬与变换思路
- Linux 面板所有对外流量都经 `services/panel/server.go` 反代到 Wails 内建服务；桌面与 server 两版都在各自 `main*.go` 里设 `application.AssetOptions.Handler` —— Range 端点就包在这一层，**两构建共用一份 handler 包装**
- `frontend/package.json`：**无** monaco/codemirror/prism/pdf.js；有 `@wangeditor`、`vue-cropper`、`echarts`。本页新增 `codemirror` 系列 + `xlsx`（均前端 npm，不影响 Go 构建）
- 工具页注册三处：`router/modules/base.ts` 的 `TOOLS[]`（自动生成 `/` 与 `/win` 两条路由）、`services/config/config.go` 的默认 `Tools` + 迁移 extras 列表、`SaveConfig` 防抹；前端「文件图标 + 面包屑」用现成 `common-file-icon` 与 `.crumbs` 模式

## 1. 后端原语：`tools/fileview/fileview.go`（新，package fileview，纯文件系统逻辑，跨平台零 cgo）

- `type FileText struct { Content string; Size int64; Truncated bool; Binary bool }`
- `ReadText(path string) (FileText, error)`
  - `filepath.Abs` + `os.Stat`（目录报错），读上限 `maxTextInline = 2 << 20`
  - 判定二进制沿用 `client_sftp.go` 写法：`bytes.IndexByte(buf, 0) >= 0 || !utf8.Valid(buf)` → `Binary=true`，只回小段
  - 超限 `Truncated=true` 并截到 `maxTextInline`
- `WriteText(path, content string) error`
  - **仅覆盖已存在文件**；写前 `maxTextInline` 上限校验
  - 先写 `path + ".part"` 再 `os.Rename` 原子落回；失败删 `.part`
- `type FileBinary struct { Kind string; DataURL string; Size int64 }`（Kind：`inline` | `tooLarge`）
- `ReadBinaryDataURL(path, mime string) (FileBinary, error)`
  - `os.ReadFile` + base64 拼 `data:<mime>;base64,...`
  - `size > maxBinInline = 25 << 20` → 返回 `tooLarge`（前端改用 Media 端点或下载）
- `OpenSystem(path string) error`：转 `sysx.Open().File(path)`（headless 自然回 `ErrUnsupported`，不吞成假成功）
- `WriteBinary(path, dataBase64 string) error`（图片/PDF 处理产物写回）：`base64.StdEncoding.DecodeString` → 先写 `path + ".part"` 再 `os.Rename`；可新建可覆盖；上限 `maxWriteBinary = 512 << 20`

### 类型判定：`Classify(path) (kind, mime string)`（同包）

三级「扩展名 → MIME → 内容嗅探」，`kind ∈ image|pdf|sheet|text|code|audio|video|binary`：

| kind | 扩展名 |
|---|---|
| image | png jpg jpeg gif webp bmp svg ico |
| pdf | pdf |
| sheet | xls xlsx csv（csv 也走 SheetJS） |
| audio | mp3 wav m4a ogg |
| video | mp4 webm mov |
| code | js ts jsx tsx vue json html css go py php sh yaml yml toml |
| text | txt md log ini conf env |
| binary | 其余 |

## 2. Range 流式端点：`tools/fileview/media.go`（新，同包）

- `MediaHandler(next http.Handler) http.Handler`
  - 仅拦 `GET /fileview/media?path=..&name=..&dl=0|1`，其余路径**原样透传 next**（不影响 assets/绑定/WS）
  - `os.Open` 后 `http.ServeContent(w, r, name, modTime, f)`：自带 Range/206/Content-Type/Last-Modified
  - `dl=1` 时先写 `Content-Disposition: attachment; filename=".."`（浏览器下载，server 构建无原生保存框靠它）
  - 拒绝目录、拒绝不存在的文件；仅文件语义
  - 无 root 约束（与 `disk` 整卷浏览一致；面板侧已在登录墙后）
- 接线两处（同一函数，包在最外层）：
  - `main.go`：`Assets: application.AssetOptions{ Handler: fileview.MediaHandler(application.AssetFileServerFS(assets)) }`
  - `main_server.go`：`Handler: fileview.MediaHandler(gzipAssets(application.AssetFileServerFS(assets), assets))`（Media 走 ServeContent 不 gzip）
- 前端音视频：`<video>/<audio> src="/fileview/media?path=..&name=.."`；大 PDF 亦可 `iframe src` 指向它

## 3. 绑定层：`services/app/fileview.go`（新，package app，方法挂 `*App`，**无 build tag，跨平台**）

- `FileReadText(path string) (fileview.FileText, error)`
- `FileWriteText(path, content string) error`
- `FileReadBinary(path, mime string) (fileview.FileBinary, error)`
- `FileOpenSystem(path string) error`
- `FileWriteBinary(path, dataBase64 string) error`：把浏览器处理产物（图片/PDF）经 `fileview.WriteBinary` 原子写回磁盘，跨平台无 build tag
- 符合 AGENTS「绑定方法不能藏在 build tag 后面」：server 构建同样存在（Linux 面板浏览的是服务器本机文件）

### 图片 / PDF 编辑操作（本次增补，前端处理为主）

按 `Classify` 的 kind 在对应 Pane 工具条追加操作按钮，处理全在浏览器（原生 canvas / pdf-lib，三构建一致、Linux 面板浏览器同样可用），Go 侧只加写回原语 `FileWriteBinary`。源经 `/fileview/media?path=..` 同域读取（图片作 `<img src>` 供 canvas 取像素，PDF 用 fetch 取 ArrayBuffer），产物经 `FileWriteBinary(path, base64)` 原子落盘，默认同目录加后缀输出、冲突提示覆盖。

| kind | 操作 | 前端实现 | 输出 |
|---|---|---|---|
| image | 压缩 | `canvas.drawImage` + `toBlob(type,quality)`（jpeg/webp 质量、或降尺寸） | 另存新图 |
| image | 格式转换 | canvas → `toDataURL(image/png\|jpeg\|webp)` 改扩展名 | 另存 |
| image | 缩放 | 指定宽/高/百分比，可选保持比例，drawImage 到目标尺寸 | 另存 |
| image | 拼接 | 多选图纵/横/宫格，canvas 累计尺寸逐张 drawImage | 合成新图 |
| image | 转PDF | pdf-lib `embedJpg/embedPng` 逐张成页（webp/gif/bmp 先 canvas 转 png/jpeg 再嵌） | 生成 .pdf |
| image | Base64 | 复用 `FileReadBinaryDataURL` 取 base64，含/不含 data 前缀 + 复制（并入原 imageBase64） | 复制文本 |
| pdf | 合并 | 多选 PDF → fetch ArrayBuffer → `PDFDocument.load`+`copyPages` 依序 → `save` | 合并 .pdf |
| pdf | 拆分 | `PDFDocument.load` → 按页范围/每页新建文档 `save` | 多个 .pdf |

- **格式支持如实**：重编码仅 png/jpeg/webp（canvas 原生）；bmp/gif/tiff/svg 只解码预览、不作转换输出（如需补全另列后端 `golang.org/x/image` PR，不引 cgo）。
- **护栏**：单文件/合并体积沿用 `maxBinInline` 量级上限，超出提示「走下载、不在浏览器内处理」；拼接设张数上限防 OOM。
- **UI 分工**：**压缩/格式转换/缩放/标注/像素输出** 全在 ImagePane 的「编辑模式」内联完成（见下「图片编辑模式」小节），不单列弹窗；仅 **拼接/转PDF**（图片，需多选）与 **合并/拆分**（PDF）走 `views/tools/viewer/components/edit/` 弹窗（`StitchModal/Image2PdfModal/PdfMergeModal/PdfSplitModal`，遵循弹窗规范）。多选支持左栏 Ctrl/Shift 或「加入待处理列表」。text/sheet/media/binary 不加编辑。

### 图片编辑模式（标注 + 像素/大小输出，本次增补，复用截图标注引擎）

图片不再只「看/压缩」，而是提供与截图页同级的**编辑工作台**。标注引擎复用仓库已有的纯逻辑模块 `@/views/widget/captureDraw.ts`（`Tool/Pt/Rect/Shape`、`drawShape`、`canvasToPngDataURL`、`normalizeRect`、`clampToScreen`、`shapeIsMeaningful`、`shouldAppendPoint`、`MOSAIC_BLOCK`），截图页 `views/tools/screenshot/index.vue` 就是拿它编排的。

**A. 抽出共享组件**（避免复制截图页那 ~500 行内联逻辑）
- 新建 `components/business/annotate-canvas/AnnotateCanvas.vue`：封装 工具栏(矩形/椭圆/箭头/画笔/**马赛克**/文字)+子栏(线宽/字号/配色)+画布舞台+编辑交互（`base` 画布承当前位图、`shapes` 为未烘焙标注、`flatten()` 合成、旋转/裁剪烘焙、视图缩放/1:1/适应、撤销 Ctrl+Z、Esc 取消）。props：源图（dataURL/`HTMLImageElement`）、可用工具集、是否显裁剪/旋转；expose：`exportDataURL()`、`naturalSize()`；`v-model` 成品。在 `components/index.ts` 三处登记（遵循全局组件规范）。
- **截图页回归**：`screenshot/index.vue` 改为「取图 + `AnnotateCanvas` + 桌面专属落盘（`SaveCaptureFile`/图钉/复制）」，只搬「预览编辑器」部分，**不动选区浮层那条 `captureDraw` 直用路径**。此为纯前端重构、零后端改动，单列一个 PR 先落地。

**B. 查看器 ImagePane 接编辑模式**
- ImagePane 顶部「查看 / 编辑」切换；编辑态内嵌 `AnnotateCanvas`。源图用 `FileReadBinaryDataURL`（≤`maxBinInline` inline）或 `/fileview/media?path=..` 同域 `<img>` 载入转 base canvas（同域→不被污染→可读像素/导出）。
- **输出面板（编辑像素/大小输出，显示/另存等）**：
  - 显示：源像素 `WxH`、文件大小、格式；编辑后实时**输出像素**（受裁剪/尺寸编辑影响）与**估算输出体积**。
  - 尺寸编辑：宽/高/百分比 + 保持比例（并入原「缩放」）；格式 png/jpeg/webp；jpeg/webp 质量滑条（并入原「压缩」）。
  - 动作：**显示**（刷新预览/尺寸）、**另存为…**（选路径 → `FileWriteBinary`）、**覆盖原图**（同路径 `FileWriteBinary`，二次确认）、**复制到剪贴板**（仅桌面 `CopyToClipboard`，非桌面按 `caps` 隐藏）、**下载**（`/fileview/media?...&dl=1`）。
  - 导出链：`flatten(base+shapes)` → 按输出尺寸重画 → `canvasToPngDataURL`/`toBlob(fmt,q)` → base64 → `FileWriteBinary`。
- 于是前表 image 的**压缩/格式转换/缩放**并入本编辑输出面板（不再单列弹窗）；**拼接/转PDF** 需多选仍是弹窗；**Base64** 是面板动作按钮。
