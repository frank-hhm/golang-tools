## 0. 诉求与现状（已核对，不是推测）

用户诉求（原话）：**「增加上传任务，进度（如现有的下载组件一样做个上传进度的组件—后续公用），切片，队列等」**。
截图证据：门户上传页一个 2.5 GB 的 ota zip 正在传，页面只有「上传中…」纯文本，无进度条、断了只能整包重来。

已核实的实现态：
- `tools/lanshare/server.go` `handleUpload`（L345-390）：`POST /upload` 一次性 multipart，`r.Body=MaxBytesReader(2<<30)` → `ParseMultipartForm(1<<20)` → 逐个 `uniqueCreate`+`io.Copy` 边收边写；**只在 `len(saved)==0` 时发一次 error、结尾发一次 done**，无中间进度、无切片、无队列。路由在 `handle`（L322）：`case POST /upload`。
- `tools/lanshare/portal.go` `indexHTML`（L86-148）：纯内联 HTML+原生 JS，`btn.onclick`（L146）用 `FormData` 一次性 `fetch('/upload')`，`msg` 全程只有「上传中…」。服务不托管静态资源——门户页必须保持纯内联。
- `tools/lanshare/pack.go`：`Progress{Op,Name,Stage,Percent,Note}` + `emitProgress("lanshare:progress", p)`，emitter 由 main 注入（`SetEmitter`）。
- `services/tasks/tasks.go`：`events["lanshare:progress"]={"lanshare","op"}`；`opVerbs["upload"]="接收上传"`；`payload` 已含 `ID`/`Status` 键（下载/云盘专用）；`identify`（L344）对 download/clouddrive 用 `p.ID` 当台账主键；`apply`（L312）对 download 把 `p.Status` 记进 `Stage` 供就地操作按钮。**lanshare 目前不带 ID/Status，所以同名会并一行、无细粒度相位。**
- `frontend/src/components/common/task-progress/index.vue`（`common-task-progress`）：纯 UI 进度行，props name/status/percent/speed/eta/meta/variant/indeterminate，emit cancel/retry/resume/open。用户口中「现有的下载组件」就是它。
- 参照范式 `tools/downloader`：分块 `Part{Index,Start,End,Done}` + 状态机 pending/queued/running/paused/done/error/canceled + `.part`/`.gtdl.json` 续传 + `MaxRunningTasks` 队列。**方向相反**：downloader 是 Go 主动拉远端，lanshare 上传是浏览器主动推到 Go 接收侧——切片/队列/暂停由发送侧（浏览器）驱动，服务端配合接收分片 + 记录会话 + 允许断点续传。

## 1. 决策摘要（已与用户确认）

| 维度 | 取定的做法 | 明确不做 |
|---|---|---|
| 切片启用 | **阈值自动**：单文件 ≥8 MiB 走 init/part/complete 切片会话（可续传、有进度）；<8 MiB 仍走一次 multipart，curl/老页面直投可用 | 不强制所有文件都切片（小文件不做三次往返） |
| 队列/暂停归属 | **发送侧**（门户页 + Vue 面板）持有队列、并发数、暂停/继续；**服务端也管**：登记会话、列会话、强踢卡死会话（新增绑定） | 服务端不代替浏览器决定何时发下一片 |
| 公用组件 | 新建 `common-upload-panel`（拖拽区 + 文件队列 + 进度行，传输函数注入）；内部用 `common-task-progress` 画行 | 不把上传 UI 散落在各页；不只做进度行约定 |
| 任务台账 | 接收侧**全程一条行**：init 起 running 并持续刷百分比，complete/error/canceled 收尾；事件按秒节流 | 不每个分片刷一行、不只在完成时记一行 |
| 门户页 | 切片队列进度在门户纯 HTML 内独立实现（同一协议、同一状态语义），**不引入 Vue、不托管静态资源** | 不让门户依赖打包产物 |

## 2. 服务端：切片接收会话协议（`tools/lanshare`，新文件 `upload_session.go`，零 cgo 跨平台）

会话态落盘 `appdirs.Data("lanshare")/uploads/<sid>/`：一个稀疏 `.part` + `meta.json`（Name/Size/ChunkSize/Done 位图/Created/UpdatedAt）。sid = 客户端上传指纹 `sha1(name|size|lastModified)` 前 16 位（同文件重传命中同会话 → 断点续传）。

路由（全部并入 `handle` switch，复用现有限频 + PIN 校验 `pinOK`）：
- `POST /upload/init`：body `{name,size}` → `{sid, chunkSize, have:[]int}`（have=已收分片下标；`sanitizeName`+`uploadBlocked` 过滤，非法名/黑名单类型直接 400）
- `PUT /upload/part?sid=&idx=`：body 为该分片原始字节 → 按 `idx*chunkSize` 用 `WriteAt` 落 `.part`、标记 idx 完成、回 `emitProgress(running, percent)`
- `POST /upload/complete?sid=`：校验分片齐 + 总大小 → `uniqueCreate(name)` 落收件箱 + 拷 `.part` 内容 → 删会话目录 → `emitProgress(done)`
- `DELETE /upload/abort?sid=`：删会话目录 → `emitProgress(canceled)`
- `GET /upload/session?sid=`：回 `{have, received}`（前端重连查进度）

护栏：`maxSessions`（默认 8，超了 init 返回 429）、`maxUploadBytes` 仍是 2 GiB/文件、会话 TTL（默认 24h）+ 每次 init 时顺带扫过期目录删除；分片大小 `chunkSize` 默认 4 MiB（与 init 响应一起下发，前端按它切）。

`Progress` 扩展（`pack.go`）：加 `ID string json:"id"`（=sid）、`Status string json:"status"`（queued|running|paused|done|error|canceled），与下载负载对齐。

## 3. 任务台账接线（`services/tasks/tasks.go`）

- `identify`：把 `meta.tool=="lanshare"` 并入「用 `p.ID` 当主键」的分支 → 接收上传全程稳定一行、重名避让出的多任务也不误并。
- `apply`：把 `p.Status` 记进 `Stage` 的条件从 `download` 扩到 `download||clouddrive||lanshare`，抽屉/lanshare 页据此渲染 queued/paused 相位与就地操作。
- 事件节流：服务端 `emitProgress(running)` 按「同一 sid 距上次 ≥1s 才发」节流（用会话里 lastEmit 时间戳），终态（done/error/canceled）必发。

## 4. 绑定层（`services/app/lanshare.go`，无 build tag，纯 net/http 跨平台）

新增两个导出方法（触发 `wails3 generate bindings -ts -i` 重生成）：
- `LanShareUploadSessions() ([]lanshare.UploadSession, error)`：列当前活跃/可续传会话（Name/Size/Received/Percent/UpdatedAt）
- `LanShareAbortUpload(sid string) error`：强踢一个卡死/占位的会话

## 5. 门户页上传改造（`tools/lanshare/portal.go` `indexHTML`，纯内联）

`btn.onclick` 重写为发送侧队列：
- 队列并发默认 2；每个文件：`<8 MiB` 走旧 `FormData /upload`；`≥8 MiB` 走 init→按 4 MiB 切片顺序/并发 `PUT part`→complete。
- 每个文件一行进度 UI（内联 CSS 手绘进度条 + 百分比 + 速度 + ETA + 暂停/继续/取消/重试按钮）；暂停=停止取后续片，继续=重新 init（拿回 have）补未传片。
- 全部走 `fetch`，切片用 `file.slice(start,end)`（Blob）。保持无静态资源依赖。
