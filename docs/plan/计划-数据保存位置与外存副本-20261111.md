## 一、需求原话与拆解

用户原话：**「我们目前的数据保存可以增加一项设置，选择保存位置（本地，mysql，redis 多选），然后选择 mysql 或 redis 下面出现对应绑定库（用我们自己的实例中选择，如果没有增加提示进行去新增等），绑定成功的在新启动时，mysql 或 redis 没启动，需在主页图1的"欢迎回来！"一栏展示提示开启。注意没选择本地而且服务没开启的情况（弹窗提示启动或选择默认数据）」**

拆成五件事：

1. 设置页新增「数据保存位置」：本地 / MySQL / Redis **多选**。
2. 勾选 MySQL 或 Redis 后，下方出现**绑定选择器**：实例从我们自己的服务实例里选（`MySQLSrvListInstances` / `RedisSrvListInstances`），再选库（MySQL 库名 / Redis DB 序号）；一个实例都没有时给"去新增"的提示与入口。
3. 绑定成功后，**新启动时**如果绑定的 MySQL/Redis 实例没在跑，在主页「欢迎回来！」卡片那一栏展示提示并可一键开启。
4. **未勾选本地且绑定的服务没启动**时弹窗：启动服务 / 本次使用默认数据。
5. 数据本身要真的写进 MySQL/Redis，而不只是设置项摆着。

## 二、已确认的四个语义（用户选择）

| 维度 | 取定的做法 |
|---|---|
| 数据范围 | **config.json + data/ 下各服务的配置缓存 JSON**（实例登记、任务台账、续传会话等）；二进制产物（截图/录像/.part/备份）不入外存 |
| 写语义 | **本地为准 + 远端副本**：本地文件永远是权威可读源，远端是持久副本；远端挂了不影响程序运行，只标脏并在恢复后自动补齐 |
| 服务未启动 | 主页常驻提示条（带「启动」按钮，直接调现有 `*SrvStart`）+ 「没勾本地」时的弹窗：**启动服务 / 本次使用默认数据** |
| 库的创建 | **自动建库建表**：MySQL `CREATE DATABASE IF NOT EXISTS tools_data`（库名可改，表 `tools_data_store`）；Redis 固定键前缀 `Tools:data:`（可选 DB 序号）。下拉同时列出已存在的库供挑选 |

## 三、「本地」勾选框到底控制什么（必须写清，否则语义自相矛盾）

本地是引导文件（`config.json` 存着绑定信息本身）与全部既有代码的读取源，**技术上不可能真正关掉**。所以这一项的含义定为：

- **勾选本地（默认）**：本地是保存位置之一，也是权威源；远端只是副本。远端不可用 → 静默标脏，不打扰。
- **取消本地**：本地降级为**临时工作缓存**——运行期照写（不改任何存量 store 代码），但：
  - 启动时**远端优先**：绑定可达且远端文档比本地新（digest 不同）时，把远端内容回写本地再交给各服务读取；
  - 主页与设置页明示「本地不再是保存位置，仅本机临时缓存」；
  - 远端不可达 = 这次启动**没有任何受管保存位置** → 触发第四节的弹窗。

这样"多选"里取消本地是有真实后果的，也不需要去改 20 多处直接 `os.ReadFile` 的存量代码。

## 四、启动时序与弹窗规则

```
main: config.LoadAppConfig()
   └─ datastore.Configure(cfg.Storage)          // 只存设置，不碰网络
App.ServiceStartup
   └─ datastore.Start(emit)                     // 后台探测：实例在不在跑、建库建表、拉远端清单
        ├─ 本地已勾选 .................. 正常，副本按脏队列补齐
        └─ 本地未勾选且远端不可达
             ├─ 记 fallback 状态（sessionLocalOverride=true 之前，本轮全程用本地）
             └─ 主页 onMounted 取 DataStoreStatus() → 弹 Modal（每次启动只弹一次）
                  [启动服务] → DataStoreStartBound(kind) → 成功后恢复远端读写
                  [本次使用默认数据] → SetSessionLocalOverride(true)，状态条转灰字提示
App.ServiceShutdown
   └─ datastore.Stop()                          // 最后一次 flush，把脏队列写完再退
```

弹窗**只在"取消本地 + 远端不可达"时弹**；只勾远端但服务在跑、或勾了本地，都只有提示条不弹窗，避免每次启动都打扰。

## 五、受管文档清单：扫描式，不硬编码文件名

`datastore` 维护的不是手工登记表，而是**扫描**：

- 纳入：`config.json`（key = `app/config.json`）+ `DataBase()` 递归深度 ≤2 下的全部 `*.json` + `npm/npmrc`。
- 排除（硬排除，UI 不给开关）：`panel/settings.json`（面板登录密码哈希与 Secret）、`*.part`、`uploads/<sid>/`、`redis-servers/`（下载缓存）、任何 `logs/` 路径、超过 `maxDocBytes`（默认 4 MiB）的文档。
- **敏感组**（含凭据，默认不同步，可在清单里逐条勾"加密后同步"）：`term/credentials.json`、`ftp/connections.json`、`clouddrive/accounts.json`、`clouddrive/uploads.json`、`docspace/secure.json`、`mysql/mysql-instances.json`（内含 RootPassword）、`redis/redis-instances.json`（内含 Password）。
  - 勾选后走 **AES-256-GCM 信封加密**再写远端，主密钥随机生成、存 `data/app/master.key`，用现有 `tools/secret`（Windows DPAPI / Linux 0600 文件权限）保护。
  - 如实写明边界：**主密钥在本机，换机器后远端密文解不开**，外存副本的跨机恢复只覆盖未加密那一组。UI 与注释都不许写成"已加密所以安全可跨机"。

## 六、远端表结构

MySQL（库名默认 `tools_data`，标识符按 `^[A-Za-z0-9_]{1,64}$` 校验后才拼进 DDL）：

```sql
CREATE TABLE IF NOT EXISTS tools_data_store (
  data_key   VARCHAR(191) NOT NULL PRIMARY KEY,   -- 文档 key（slash 相对路径）
  payload    LONGBLOB     NOT NULL,
  digest     CHAR(64)     NOT NULL,               -- 本地文件 sha256 hex
  size_bytes BIGINT       NOT NULL,
  encrypted  TINYINT      NOT NULL DEFAULT 0,
  app_version VARCHAR(32) NOT NULL DEFAULT '',
  synced_at  DATETIME(3)  NOT NULL,
  updated_at TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

Redis：`Tools:data:<key>` 存 payload（二进制安全，值里带 `enc:v1:` 前缀标记信封），`Tools:data:__meta__` 是 hash，field=key、value=`{"digest":..,"size":..,"enc":..,"syncedAt":..}`。不做 TTL（外存副本不是缓存）。

读写都走**参数绑定**，不拼 SQL 正文；DDL 里的库名是唯一需要拼接的地方，先校验再用。

## 七、同步引擎（脏队列 + 收敛）

- 变更发现：`datastore` 起一个 ticker（默认 5s，`document` 隐藏时不提速）扫受管文档的 `mtime+size+sha256`，与上次快照不同就入脏队列。**零侵入存量 store**——不要求任何地方调我们的 Save helper。
- 补齐时机：入队即尝试发送；失败留队列（上限 200 条，超了丢最旧并计数告警）；`ServiceShutdown` 与「立即同步」按钮做强制 flush；实例启动成功后由提示条回调触发一次全量比对。
- 失败可见性：每个 sink 记 `lastError`、`pendingCount`、`lastSyncAt`，全部进 `DataStoreStatus`，设置页与主页提示条都读它。
- 远端优先回写（仅"取消本地"时启用）：启动后比对 digest，远端新 → 原子写本地（tmp+rename），并广播 `config:saved` 让已开的页面重取。

## 九、明确不做

- 不把 MySQL/Redis 当配置的真源去改各 store 的读写路径（存量 20+ 处直接读文件，改动面与回归面都太大）。
- 不做多机之间的冲突解决（只有"本机远端优先"一条规则，跨机同改按最后写入覆盖，UI 里写明）。
- 不做第三方云（那是 `tools/clouddrive` 的事）。
- 不动 `panel/settings.json`：面板账号密码与 Secret 永不出本机。
- 不引入新依赖（MySQL 驱动、x/crypto、RESP 客户端都在）。
